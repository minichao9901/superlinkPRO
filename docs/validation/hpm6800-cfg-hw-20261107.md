# HPM6800EVK 的 WebUSB CFG 与 RAM 调试验收

2026-11-07（北京时间）。源码基线 `ee00aa3cce6ba02cdba4e12a360eba2dc0d34b3c` 加本地改动，验证对象为 Chrome 156、akaLinkPro 和 HPM6800EVK 的 HPM6880 hart 0。源码模块和合并包均导入 SDK v1.11.0 原版 `hpm6800evk.cfg`，真机运行使用合并包。

| 步骤 | 实测 |
|---|---|
| 导入及连接 | 选中 `hpm6880.cpu0`，JTAG 8 MHz，TAP `0x1000563D`，IR 5，DTMCS `0x00007071`，32 位 SBA |
| RAM ELF 下载 | 唯一 `PT_LOAD` 为 ILM `0x00018000` 起 20 字节，经页面 `load_image` 写入并逐字节回读一致 |
| 运行到 `main` | 设置 PC 到 `_start` 后执行 `rc main`，运行到 `0x00018008`，源码高亮第 14 行，`a0=0` |
| 两次 F10 | 停在 `0x0001800C` 和 `0x00018010`，高亮第 16、18 行，`a0=1、2` |
| 恢复 | 回写并核对原 20 字节 ILM、原 PC、`a0` 与 DCSR 可恢复部分，确认原固件继续运行后断开 |

目标的 JTAG、DMI、SBA、断点和步进经 WebUSB/CMSIS-DAP。常规连接使用浏览器 WebHID 设置探针引脚模式。探针处于 JTAG 模式后，另起一轮从页面加载前屏蔽 WebHID，完整重跑也通过。验收脚本在停核后通过同一 WebUSB 调试会话执行 `fence.i`，再从页面设置入口。脚本限定目标存储器写入为 ILM `[0x00018000, 0x00018014)`，最终记录两笔，分别为下载和恢复。CFG 的 Flash bank、DDR 初始化和 GDB 连接复位事件不执行，验收未读取外部 Flash 哈希。 [机器证据](hpm6800-cfg-hw-20261107.json)

预检的直接 IDCODE 命令曾返回全 1，改用工作台的实际 TAP 扫描序列后，1 MHz 和 8 MHz 均得到正确 ID。首轮调试链路已通过，恢复脚本按 DCSR 整字比较时因只读 `cause` 从暂停请求变为触发器命中而报错。复核 ILM 和原寄存器后恢复运行，修正比较掩码后完整重跑通过。 [RISC-V DCSR 定义](https://github.com/riscv/riscv-debug-spec/blob/main/xml/core_registers.xml)

## 复现

确认 HPM6800EVK 已经上电、JTAG 已接、设备空闲。用已授权 akaLinkPro 的 Chrome 在 CDP 9333 打开本地工作台。脚本使用新的输出目录保留 ILM 备份和复测记录。

```powershell
$out = 'tmp/hpm6800-cfg-FRESH'
$fixture = 'web/tools/selftest/fixtures/dbg-cfg'
$sdk = 'E:/sdk_env_v1.11.0/hpm_sdk'
New-Item -ItemType Directory $out
clang --target=riscv32-none-elf -march=rv32im -mabi=ilp32 -gdwarf-4 -nostdlib -fuse-ld=lld `
  "-Wl,-T,$fixture/hpm6800_ram.ld" '-Wl,--nmagic' "$fixture/hpm6800_ram.S" -o "$out/hpm6800_ram.elf"
node web/tools/selftest/dbg-hpm6800-cfg-hw.mjs $out "$sdk/boards/openocd/boards/hpm6800evk.cfg"
```

在已配置 JTAG 的探针上，使用新的输出目录并追加 `--webusb-only` 可复现屏蔽 WebHID 的验收。
