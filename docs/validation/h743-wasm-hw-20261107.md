四档由工作台 CLI 驱动生产网页联动，先经 Wasm 校验目标 Flash 和时钟、配置 ETM / ETF / TPIU，再由 Kingst 录制并保存 KVDAT。随后用工作台的 `trace decode` 入口走原生紧凑链。四档严格 `verify` 通过，输入指纹一致，包问题均为 0。紧凑处理时间包含物理取样、OpenCSD 和索引，排除 LA 回传、浏览器渲染及输入复制。每档本轮各报一次，历史为三次，ETM 配置和重建后的 ELF 不同。1 s 紧凑处理仍超过历史 10 s 目标。首个页面服务默认走文本和 SQLite，200/500 ms 的旧链路同样通过解码质量检查，但页面总时长分别为 82.60 / 191.25 s。原生进程初试因系统 TEMP 无法写入报告失败，改用任务内 TEMP/TMP 后成功。

首次连续负载脚本在 500 ms 开始前因 USB CDC 写超时停止。四档最终重采采用约 4 ms 间隔，并限制在任一时刻仅一条待回显请求，整轮 6,658 发、6,658 收，无 CRC 错误、重复、丢失或串口异常。四份解码均含 `handle_command`、`cdc_write`、`OTG_FS_IRQHandler` 和 `usbd_cdc_acm_bulk_out`。最终带匹配 ELF、源码快照、配置、输入指纹及紧凑记录的四档保存在 `etm/records/baselines/h743-cdc/wasm-60-20-20261107/`。Kingst 预设验收后已恢复，文件哈希对账一致。

四档验证首、中、末页查询。200 ms 样本导出简化 C/HTML、完整 C 和 CSV，`.etmrecord` 导入后原始波形和 ELF 指纹、摘要及质量结论一致。1 s 样本通过深页筛选，关闭周期计数时拒绝按周期权重导出火焰图，失败后再次严格验真通过。
