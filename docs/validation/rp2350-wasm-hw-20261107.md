# RP2350 Cortex-M33 工作台 Wasm 真机验收

2026-11-07（北京时间）。源码基线 `73e4b82` 加工作区改动。通过 8911 工作台 CLI、akaLinkPro、1 MHz SWD 和现有 OpenOCD Wasm 核心 `9f2d876`。真机回读 DPIDR `0x4c013477`、CPUID `0x411fd210` 和 SYSINFO CHIP_ID `0x20004927`。验收针对 Cortex-M33 的 0 号核。

原版 `target/rp2350.cfg` 导入工作台时，现有受限 CFG 解析器在默认双核列表 `cm0 cm1` 处明确拒绝。现有调试导入只提取支持范围内的配置，不把脚本声明的 Flash bank 交给烧录页或 RTT Viewer。离线将同一原版脚本交给仓库的 OpenOCD Wasm 核心解析，成功注册 `rp2350.cm0`、`rp2350.cm1` 和 `rp2xxx` Flash bank（XIP `0x10000000`）。该离线检查没有连接目标。见 [原厂芯片资料](https://www.raspberrypi.com/documentation/microcontrollers/microcontroller-chips.html) 和 [Pico SDK 2.2.0](https://github.com/raspberrypi/pico-sdk/tree/2.2.0)。

本轮三页使用同一 RP2350 单核预设验证。预设采用原版 CFG 的 ADIv6、AP `0x2000`、`rp2xxx`、64 KiB 备份型工作区和 XIP 地址。烧录前两次读取并对账首 16 KiB。用 Pico SDK 2.2.0 的 `pico2`、`rp2350-arm-s` 选项构建测试 ELF，SHA-256 为 `ffe7b30ab986407b2829548bdb02ae647057dc938b9b1ea262393f391cf3a1a7`。工作台按 ELF LMA 烧录 `0x10000000` 起 14,692 B，覆盖四个扇区，逐扇区读回及软件复位通过。烧录操作本次约 3.43 s。

Wasm 调试同一会话通过五项检查。复位后固件心跳持续增加，源码单步跳过、进入和跳出均有实际落点，连续八步指令单步成功，寄存器可读，SRAM 写入回读后恢复原值，连续 40 轮断点停走通过。清空后直接读回 FPB 寄存器确认没有启用的比较器。

RTT Viewer 首轮只把 SWD 时钟传给生成配置，丢失所选芯片系列，因而使用通用 DAP 连接并失败。补齐 RP2350 系列参数后，以 ELF 找到 `_SEGGER_RTT`（`0x2000077c`），实收 1,354 条心跳，下行唯一标记的回显逐字节一致，覆盖和错位读计数均为 0。

测试结束将原首 16 KiB 烧回、逐扇区校验并软件复位。重新连接后从 XIP 独立读取，SHA-256 `1874f3e74596b9ebb855d431823bf1dfef760d32153585f84b19b7e10d59ae18` 与接入时一致。调试和 Viewer 均已断开，探针锁已释放。本次未覆盖 Cortex-M33 1 号核、Hazard3 或探针固件 RTT 转发。 [机器验收数据](rp2350-wasm-hw-20261107.json)
