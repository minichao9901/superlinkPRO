# STM32F103ZE 工作台 Wasm 与高速通道验收

2026-11-07（北京时间）。用 8911 工作台 CLI 和 akaLinkPro。源码为 `73e4b82` 加工作区改动，OpenOCD Wasm 基于 `9f2d876`。SWD 回读 DPIDR `0x1ba01477`、Cortex-M3 `0x411fc231`、DEV_ID `0x414` 和 512 KiB Flash。没有用本机 OpenOCD。工作台设置和硬件操作串行执行，CDC 的数据计时从主机串口读取。

OpenOCD `init` 已完成 Cortex-M3 检查，但首次读取 `curstate` 仍可能得到 `unknown`。共享 Wasm 探针连接在 Cortex-M 遇到该状态时主动执行一次 `poll` 再核对，刷新后通过真机身份读取。Wasm 烧录页在 1 MHz SWD 下写入并逐扇区读回 `dbgstress` 的 9,820 B，随后执行软件复位，调试页读到 `g_ticks` 持续增长。三种 RTT 镜像和 72 MHz Scope 镜像亦通过读回和复位。各镜像仅写目标 Flash 起始 16 KiB 内，修改前已读出原数据。

调试初轮两次复现同一问题。四断点轮转通过，回到 `engine_linear` 当前断点后继续时，OpenOCD 会话意外关闭。Cortex-M Wasm 单步现使用 `cortex_m maskisr steponly`，避免 OpenOCD 的自动中断模式另占一个工作台管理的 FPB 比较器。恢复断点失败时保留单步原始错误。新版使用同一 1 MHz SWD 连接通过 8 项检查，包括四断点 12 次轮转、19 步指令单步、19 步源码跳过、40 轮断点停走、复位并停和复位并运行各两轮，以及寄存器、RAM 和 Flash 数据读取。源码步进后和 40 轮清空后，直接读回 FPB 寄存器确认无启用的比较器。

J-Scope 使用生产工作台 `0xa1` 配置。预热后从两次探针原子计数之差计算约 8 秒稳定窗速率。三档稳定窗 USB 丢样和读取错误为 0，完整采样的包序缺口和停采尾差均为 0。从运行中的 Wasm 调试交给 J-Scope，调试器释放后正常采样。另一次 J-Scope 独立开采后直接切回 Wasm 调试，接收 14,064 个样本，停采尾差为 0。

验收结束通过 Wasm 恢复 Flash 起始 16 KiB，软件复位后用独立 Wasm 调试会话再次读取，SHA-256 与接入时一致，均为 `5d67922babe92063c34f685f4c23812f99dc5bce65a306fa59fc8f99d6ff93eb`。调试会话已断开，探针占用锁已释放。 [机器验收数据](f103ze-wasm-hw-20261107.json)
