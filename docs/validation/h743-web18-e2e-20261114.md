# STM32H743 与 akaLinkPro 工作台端到端验收

2026-11-14，北京时间。验证对象为 Windows 冻结候选 `1.1.0-web.18`，源码基线 `4ce5e62` 加本地工作区，包标识 `88f4ba47fb849a4b758e916b0e81cc25087dde3e05979dcbd9933cc7957e35f7`。ZIP SHA-256 `65b7c88d031b46acef0111214649bc85f6c7e4474097f3411374d48a42b02586`。Chrome 145 加载合并页面，使用真实 WebUSB、WebHID 和 Web Serial。测试配置仅复用既有授权，选择器调用为 0。COM34 对应 akaLinkPro 固件 0.1，构建 2026/11/09 07:08:33，序列号 `B4444F2110DDDAFE44800BBB0AE800E0`。

## 目标连接、烧录和恢复

- 用延后 CPU 检查的原版 H7 CFG 从 AP2 读到 `DBGMCU_IDCODE=0x20036450`、初始 `DBGMCU_CR=0`。正常路径确认 `CPUID=0x411fc271`、`DPIDR=0x6ba02477`、Flash 2 MiB。官方 CFG 连接成功后 AP2 独立回读 `DBGMCU_CR=0x0070003f`。当前初态 `VTOR=0x08000000`、`MPU_CTRL=0`，覆盖 Flash 运行态的零值条件。SDRAM + MPU 开启的初态留待复验。
- 烧录页在 SWD 10 MHz 下完成原 RTT ELF 的 1,192 B 重写及校验、J-Scope ELF 的 1,240 B 烧录及校验，再写回原首个 128 KiB 扇区。每次烧录后都确认软件复位并运行。Scope 固件期间首扇区以外逐字节一致。烧前两份 2 MiB 备份、重写原 ELF 后的读回、恢复后的两份独立读回全部一致。整片 SHA-256 为 `7b6a4f9e7b83de0b9cf81236fe38508b5bcd519b7dc85fd9b811befdb77e666b`。
- 顶栏调试完成暂停、读取 PC、指令单步、继续和 SRAM 32 B 写入读回及原值恢复。Scope 固件首轮有一次单步返回 `not halted`，重新连接后 PC 从 `0x080002a0` 到 `0x080002a2`。恢复 RTT 固件后，12 轮暂停、单步和继续全部通过。
- 顶栏 NRST 按钮发送硬复位，运行计数从 95,295 ms 回到 1,323 ms，随后恢复 480 MHz 运行。最终 CFSR/HFSR 为 0，FPB 比较器全空。探针占用、等待和失败列表为空。

## RTT

RTT 测速用接入时已经在板上的 480 MHz / HCLK 240 MHz 固件，RTT 控制块 `0x24000014`。吞吐采用浏览器实际收取字节与墙钟窗口，MB/s 为十进制。

| 通路 | SWD | 实收 |
| --- | ---: | ---: |
| RTT Viewer / Wasm | 1 MHz | 0.076 MB/s |
| RTT Viewer / Wasm | 10 MHz | 0.391 MB/s |
| RTT Viewer / Wasm | 45 MHz | 0.636 MB/s |
| RTT Viewer / Wasm | 60 MHz | 0.669 MB/s |
| RTT → CDC，2048 B 批次 | 45 MHz | 2.580 MB/s（12.016 s） |
| RTT → CDC，2048 B 批次 | 60 MHz | 3.049 MB/s（三轮各约 15 s） |

Viewer 四档覆盖、错位读计数为零。下行经页面发送 19 B 标记，独立从目标下行缓冲读回并核对写指针。应用本身持续产流且不回显。

四轮 CDC 原始捕获共 175,364,096 B。各轮保存字节与探针 STOP 后的 `moved` 相等，SWD 读错、写指针错误、重新扫描、串口读取异常均为 0。四个稳态窗口按首个完整周期独立对齐，逐字节符合 `hello world!\n`。首轮原始捕获的已知启动横幅也包含在计数内。重复文本无法独立判断整周期丢失；另用 45／60／60／45 MHz 的四组非重复 15,744 B 数据覆盖这一项，浏览器原始输出、探针计数和目标读指针逐轮一致。临时 16 KiB AXI SRAM 逐字节恢复。

初筛一轮 60 MHz 曾被在线脚本报为不匹配。脚本用一个字符猜文本相位，实际误计 25,813,622 B，恰好等于该窗口从相位 9 误锁到相位 2 的周期差。复测用完整周期独立验证并保留原始字节，三轮 60 MHz 稳态数据均一致。

Viewer 运行时直接从顶栏切入 RTT 转发，Viewer 正常让出。60 MHz 转发约 10 秒后从 J-Scope 顶栏接管，RTT 停止并回到 UART，COM34 仍打开。J-Scope 在同一原 RTT 固件上采集 `g_loops`、`g_ms`，约 100 k 组/s，共 301,058 组，12 次采样前跳拍，收尾差 0。

## 轨迹范围

- ETM 顶栏真机连接、ETMv4 寄存器识别、RCC 读回和断开通过。现场未枚举 Kingst，Socket 23367 未监听，未录新波形。
- SWO 能识别 H743，读回目标及接收配置。SysTick 起点未命中，复位到 main 的路径报清理失败。在已暂停 PC 开始的尝试确认 15 Mbaud、ACPR 31，COM34 收到 0 字节。观察到上一轮的 FPB 记录仍存在，但比较器实际已等于原值。经现场读回后清除失效记录，再执行生产停止逻辑，回读确认 trace 和接收配置恢复。缺少有效 SWO 数据，接线与起点控制需分别复核。
- SPI→CDC 并发、屏幕和外接总线事务需要相应数据线或外设。本轮未执行带载采集。
