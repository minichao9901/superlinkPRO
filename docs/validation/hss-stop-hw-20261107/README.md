## 停止与连续重开

首版候选收到 STOP 后停采，状态一直为 stopping，既没有提交半包也没有发送 USB 结束标记。
原因是主循环只在前四个服务标志中有事件时调用 sampler，而 STOP 清掉运行标志后，收尾标志在门控之外。
修正版让门控也检查收尾标志。原有模型直接调用 poll，未覆盖这个入口。本次新增模型断言验证 STOP 和空读退场都能唤醒主循环。

| 方法 | 真机结果 |
| --- | --- |
| 生产 JS 停止握手，Node USB 单笔 512 B | 同一连接连续 4 轮，实际覆盖 0 B 结束读，每轮计数一致 |
| 有序 libusb，单字/八变量交替，3～7 笔 4096/8192 B 预读 | 同一 USB 认领连续 12 轮，74,147 样本逐轮等于 produced，12 个半包；其中一轮结束读为 0 B。其余空读逐笔确认结束 |
| 生产 JS 停止握手，COM43 保持 CDC OUT | 6 轮均收齐半包，756 样本逐轮与 produced 一致，CDC 主机侧写入 2,652 B、发送错误 0，收尾发起 USB 复位 0 次 |

Node USB 多笔读的早期对照出现提交乱序，单次八变量共收到 971/971 个样本，但包序出现倒退。
使用与历史测速相同的 libusb 顺序提交和顺序交付后，12 轮重开与正式测速均无包序错误。
另保留一次测试工具采用 300 ms 读超时的慢档中断记录。将测试请求超时放宽后完成慢档矩阵。
浏览器原生授权及真实 SPI 数据负载仍待验收。

## 同条件速率

额定 72 MHz F103ZE、请求 SWD 60 MHz、FAST_BATCH/CDC_OFF/ALLOW60（`0xa1`）、

正式及复测 12 个窗口的整段采集共收 26,262,626 个样本或组，逐轮等于探针 produced。

前置 500 档试跑还保留一轮 USB 无缓冲丢样 590，已生成样本亦全部收到。
USB 缓冲耗尽发生在样本生成之前，单独记账；尾包检查统计的是已经生成的样本。

## SPI 并发与恢复

现场只有 SWD，缺少 F103 SPI1 到探针 SPI2 的数据接线。SPI 传输与 CDC 转发带载验收仍待完成。
尝试认领 SPI USB 端点时，原生适配器报告探针 MI_05 缺少 `DeviceInterfaceGUIDs`。
只读核实该接口运行 WINUSB 服务、属性缺失，MI_00 的既有 GUID 仍在。按 ISSUE-040 记录。
当前分支保留为候选，合入条件等待 SPI 数据并发通过。

DFU 备份并验证原探针应用，测试后读回整个 901,120 B 应用可读区域，SHA-256 与备份一致
`0953c57df390740ec3fa5b68f6e034fd919fc136c7279ec57352165e76d55595`，原应用 `2026/10/18 21:41:39` 重新枚举。
F103ZE 仅恢复本次改动的前 4 KiB，整片 512 KiB 读回 SHA-256 仍为
`48f226217497607c696a156addbb363925577499b00ee64f187bd5eea7a94499`，48 MHz 运行，CFSR/HFSR 均为 0。
恢复目标 CDC 后复现 ISSUE-047 的 COM34 配置错误 31，按原方法重启该目标 USB 实例后 PING/PONG 通过。
