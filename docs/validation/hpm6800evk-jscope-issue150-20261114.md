# ISSUE-150 · HPM6800EVK J-Scope 历史快档与 STOP

2026-11-14（北京时间），同一 HPM6800EVK／akaLinkPro EVKLite，探针序列号 `B4444F2110DDDAFE44800BBB0AE800E0`，目标 TAP `0x1000563d`。沿用仓库 Scope ELF（SHA-256 `e5124ca35a872c2c54f210df99c5cfc3ca7a0d8f6a64f1cfa29a907aeb9b73a9`）和 `g_v` 的 1／3／8 个连续 32 位变量，单 span，RISC-V DMI idle 8，CDC 暂停、FAST_BATCH 开启。未外测 TCK。Web 使用真实 Chrome WebUSB／WebHID，CLI 使用有序 libusb bulk IN 预读与 HID。稳态窗口取探针 24 MHz 计数快照差，STOP 总量含预热和尾部。

相同探针 APP 上，Web 与 CLI 的跳拍率接近，原始 DATA 时间轴也显示采样缺口，读错与包序缺口均为零。探针在样本调度超过 deadline 时累加跳拍。采样、DMI 与组包热路径移入 ILM 后，三／八路历史周期短测的跳拍均降为 0；单路继续让 16 拍批次跨越 DATA 边界后，101 tick 由约 0.104% 降到约 0.053%。这是同板改动对照，未用硬件计数器逐周期拆分 XIP、USB 中断与其余调度开销。

旧 Web 另外出现 USB 缓冲耗尽，CLI 同档为零。Web 将高速预读调整到约 500 ms、最多 32 笔 × 32 KiB。刻意阻塞页面主线程 330 ms 的压力轮仍可见 USB 丢样，常规 60 秒结果见下。保留 HPM EP 0x83 的 STOP、最后 DATA、ZLP 与 action 13 退役协议。候选 APP SHA-256 为 `3d273d5b64721268cb521807352bfef643d703ce026ad531c869d61674da7e6c`，DFU 写后读回与同序列号重枚举通过。
