# ISSUE-149 · HPM6800EVK XIP 回读与连续 RTT 转发

2026-11-14（北京时间），同一块 HPM6800EVK（TAP `0x1000563d`）、同一支 akaLinkPro EVKLite（web.19 发布 APP，SHA-256 `cd708c27b5ff9effd621cb17b4fea9d51dde8fe71d05684dd43137d3d25b7ff0`）。开测前两次回读 XPI 前 64 KiB，一致。Flash 读写的 OpenOCD 请求档为 8 MHz，探针内 RISC-V DMI idle 为 8，搬运块 2,048 B。未外测 TCK。

## 触发条件与修复

每轮先通过 DMI 系统复位，运行同一旧 `hello world!` flood ELF。每次只改变随后执行的回读步骤。暂停、恢复以及直接 `dump_image` 回读 64 KiB 均能持续转发，约 1.45 MB/s。单独执行 `flash probe 0` 后恢复运行，即可复现稳态 0 B 与 OpenOCD 无法暂停 hart（`dmstatus=0x00400ca2`）。同轮回读加 `flash read_bank` 也复现，回读数据的 SHA-256 仍正确。跳过验收脚本的二次 `flash probe`，网页正常烧录并复位之后，原生转发 5 秒稳态恢复到 1.452 MB/s。更换目标负载或探针 APP 无需作为修复条件。

OpenOCD `hpm_xpi` 探测会在目标上执行 Flash 算法，调用 ROM `auto_config` 并重新配置正在使用的 XPI 控制器。修改后的 HPM 字节校验读映射区，调试页独立校验无需再探测 Flash bank；烧录的擦写前几何校验仍由 SDK 官方 CFG 和 `hpm_xpi` 驱动执行，烧录后复位。独立回读也直接读映射区。DMI 系统复位能从旧路径造成的故障恢复。A/B 证据在 `tmp/issue149-20261114/case-*`。Flash、RISC-V 调试及 H7 的定向软件回归通过。

## 60 秒长测

两轮使用同一带序号 XIP ELF。它沿用原 flood 的 SEGGER 阻塞写入与 32 KiB 非缓存环，仅用 13 B 的 `seq 0000000\r\n` 递增序列替代固定文本和启动横幅。临时源码、SDK 构建产物与原始采集在 `tmp/issue149-20261114/`。ELF SHA-256 为 `b8bd07e08d16476e5333f16f9faa305b187602df9aedbc6bf7a51492ac9e531f`。网页从顶栏连接，走 WebHID 启停、Web Serial 收数；原生 CLI 使用 HID 0x31 和同一 Windows CDC COM34。复用已授权设备，Chrome 选择器调用 0。
