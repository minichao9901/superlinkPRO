# HPM6800EVK OpenOCD Wasm Flash 真机验收

2026-11-07（北京时间）。在源码基线 `ee00aa3cce6ba02cdba4e12a360eba2dc0d34b3c` 加工作区改动上，用 `toolbox.py` 驱动 Chrome 156 的本地执行页。浏览器执行 OpenOCD `9f2d8762b3a75b4d7b2155affcf3d8bb8eb8849a` 的 Wasm，并通过 akaLinkPro 的 WebUSB/CMSIS-DAP v2 接口和 8 MHz JTAG 操作目标。使用原版 HPM SDK 1.11.0 `hpm6800_all_in_one.cfg` 及其依赖，TAP 实测 `0x1000563d`。CFG 加载后沿用 RAM 验收时的复位钩子限制。全程未运行本机 OpenOCD。 [机器证据](hpm6800-wasm-flash-20261107.json)

烧录对象为仓库的 HPM6800EVK J-Scope XIP ELF，入口 `0x80003000`。Flash 驱动实测容量为 16 MiB、扇区大小 4 KiB。Wasm `hpm_xpi` 擦写了扇区 0–1 和 3–13。先读取待擦扇区以保留镜像未覆盖的字节，再逐字节校验全部 53,248 字节。扇区 2 跳过。 [验收 ELF](../../web/tools/target-firmware/hpm6800evk_scope/fw.elf)

首次使用 OpenOCD 复合复位命令时超时。通过 Wasm 重连后确认应用已在 XIP 执行。第二次用 DMI 复位并尝试停在 `main` 时，OpenOCD 报告寄存器缓存状态冲突。最终流程在复位前清空寄存器缓存，再通过同一 Wasm 会话发送系统复位脉冲，回读确认 `dmcontrol=0x1`、`dmstatus=0x004f0ca2`，有新的复位标志且目标已运行。两次采样的 PC 均为 XIP `0x80005b1e`，`SCOP=0x53434f50`，计数从 `8265` 增到 `19244`。这轮另外复核了既有 ELF 的全部 47,856 个有效字节，随后断开探针并让应用继续运行。 [Wasm 会话实现](../../web/app/dbg/openocd-session.js)

最初两次烧录尝试在擦除前停止。`hpm_xpi` 打印扇区表后以「不支持保护查询」返回错误，Tcl 适配现只接受该返回码并保留扇区表，另外要求 `flash probe` 成功和待擦扇区几何完全匹配。相关调试和 CLI 回归通过，Web 合并包与 CLI 生成清单一致。本轮验收对象是本地源码工作台和这块 HPM6800EVK。

在已授权的 `#dbg` 执行页复现。该命令会写入固定验收镜像。只复核已经烧录的镜像时，加 `--verify-existing`。

```powershell
python -X utf8 web/tools/selftest/dbg-hpm6800-wasm-flash-hw.py <运行时目录> <SDK的boards/openocd目录> <新证据目录>
```
