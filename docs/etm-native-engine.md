# ETM 原生链路实验版

本分支把 KVDAT 物理前端、OpenCSD 二进制输出、原生执行事实、完整查询索引与
网页浏览连接起来。目标是减少首屏等待，仍保留质量诊断、谓词未知、异常、
周期、原始包字节和源码定位。它尚不是持续采集和持续解码的流式系统。

## 使用

源码运行时显式设置 `ETM_STORE_WRITE=1`、`ETM_STORE_ENGINE=native`。
从 **1.0.14-native.9** 起，便携 EXE 默认启用完整原生优化链路，双击 BAT 即可，
不需要环境变量或 `--engine native`。随包 `etm.config.json` 显式写入 `"engine": "native"`；
配置缺失或旧配置仅含端口时同样默认 native。启动日志与 `/etm-launcher.json` 显示实际选择。
缺少原生程序或能力不匹配会报错，不会静默回退。

需要对照排查时，运行 `etm-bridge.exe --engine python`，或把配置的 engine 改为 python，
退出并重新启动工作台。优先级为命令行、配置、默认 native；auto 等同 native。
便携入口统一启用融合写出、二进制输出和 fast 展开，覆盖当前进程继承的旧实验开关，
不修改系统环境变量。已有记录不会自动重解码；新解码使用所选引擎，兼容的已建查询索引
会自动使用数值行锚点优化。源码独立服务的环境变量默认行为保持不变。

单次采集默认上限保持 **200ms**。尚未完成连续 500ms／1s 的 H743、akaLinkPro、
Kingst 真机验收；合成规模测试不能替代真机采集。`1.0.14-native.10` 的已验收离线包
已同步到本分支的 `web/bridge/etm/downloads/`，供版本标签与分支下载使用。
线上站点由 main 分支的 Pages 工作流发布，是否已更新须核对线上下载清单，
不能把当前分支或本地包的版本当作线上版本。

### 导出

`1.0.14-native.10` 起，原生记录与旧流式记录都支持整段或所选执行区间的
简化源码 C、源码对照 HTML、完整源码执行流 C、执行流 CSV。服务端逐事件写文件，
不把整段执行事件放入内存；HTML 仍保留简化行、未知状态与原始源码的离线对照。
很大的离线 HTML 在打开时仍需浏览器加载其中数据，可优先导出局部区间。

前三种格式需要配套源码正文；ELF 的 DWARF 路径和行号不包含正文。记录没有任何
非空源码时，页面提示从“4 文件”的“配套源码设置”载入对应源码，不再生成只有
“无配套源码”的大型 C 文件。部分缺失位置仍保留诊断。CSV 不依赖源码正文。
页面先检查导出响应，错误留在页面，不再把错误 JSON 当作下载；服务端生成/响应等待上限
仍为 45 秒。成功响应后的大文件传输不计入同一个总时长，避免已生成的文件因传输时间被误判超时。

`1.0.14-native.11` 增加默认的 C++ 导出器 `etm_export`：对既有 trace-store 直接读取
RUN、执行状态和稀有事件，只准备一次静态源码/文本模板，不逐条构造 Python 事件字典，
也不恢复导出不需要的调用路径。支持简化 C、完整 C、离线 HTML 和 CSV，沿用现有
合并规则、字段顺序、UTF-8/BOM、CSV 引号及未知/缺失位置诊断；存储格式不变，
已有 trace-store 无需重解码即可受益。

默认按请求选择路径：大范围使用 C++；已准备好数值行读取表、且不超过4096条记录的
小范围使用原有索引投影，避免原生进程和全份校验固定成本。未准备/不支持的旧索引
不用于该小范围选择，防止重新进入从头状态重放。`ETM_EXPORT_ENGINE=native` 可强制
原生对照，`python` 可强制原Python路径。

原生导出持有已验证 generation 的借用，校验存储 SHA、头部和序列 CRC、变长整数、
解压长度、状态/静态 ID/事件计数及输出指纹；结果先写私有临时文件，全部成功后替换输出。
它只投影导出所需字段，不作为继续解码或恢复 CallTracker 的状态检查点。
完整便携包缺失/版本不符的导出器明确报错，不把回退当作原生成功。
旧 JSONL/内联记录及源码环境未构建辅助程序时仍保留 Python 入口。
开发对照可设置 `ETM_EXPORT_ENGINE=python`；`--engine` 仍只选择解码引擎。
性能数据以对应验证报告为准，输出体积、打开存储、HTTP 和浏览器绘制需分别计时。

## 链路与格式

1. 原生物理前端直接读取 KVDAT，完成滤波、DDR 取样、TPIU 解复用，免去 CSV。
2. OpenCSD 写出二进制元素与包，避免逐包格式化文本。
3. 唯一代码范围只反汇编一次；原生构建器同遍产出执行序列、完整分析与 ETMFACT3，
   复用唯一范围的指令编码，并生成热点、PC 单元格和源码区间的数值归约。
4. NumPy 批量构建其余查询表及默认视图；窗口按路径极值和区间归约计算，
   索引表最多四个线程并行压缩，目录顺序和编码保持确定性。
5. 最后原子替换 manifest；异常时保留上一代，并恢复更新前的兼容元数据。

ETMFACT3 的 RUNS 是每 4096 条指令一个的定位锚点，包含原始 RUN 内的 runSkip，
不再为每个动态 RUN 复制一整行事实。事件、周期与路径保持稀疏。
事实静态 ID 使用核心存储首次出现的顺序，不能混用按 PC 排序的传输字典 ID。
临时事实和中间核心副本在发布成功后清理；原始采集文件不修改。

两个字节相位分别保留解析失败状态，到整段收尾时再判定是否恰好一个候选有效。
一个相位遇到坏帧不会终止另一个候选；两者均无效或均有效仍明确拒绝，保留失败诊断。

数值归约的临时格式为 `ETMIDXF1`，绑定同一 native.bin 的 SHA256，验证尺寸与
静态 ID 映射后才参与索引构建。旧辅助程序未声明能力时保留 NumPy 兼容路径；
持久存储仍使用原有查询块 v2，不依赖外置 sidecar。

较大的执行序列使用现有容器压缩标志保存，定位偏移仍指向解压后的序列。
包块保留记录数语义；发布容器直接写到预留好目录的临时文件，避免再次复制整份 payload。
文件 CRC、完整 SHA256、fsync 和 manifest 最终发布仍执行。

无筛选、连续执行序号的区间分页直接按端点计算总行数，避免为计数扫描整段。
有完整查询索引的记录使用现有 4096 指令定位锚点和持久调用路径区间直接还原行，
深页、单事件及所选位置的历史调用路径不再从头重放 CallTracker，既有记录无需重解码。
正常输入最多跳过一个数值单元格，展开段最多 4096 条指令；初始化只加载行定位相关表。
这仅用于读取行，不将数值锚点冒充可恢复状态机的执行检查点。
旧记录无索引或不支持的索引使用原路径；准备阶段校验失败记录索引问题后回退，
已开始返回行后的数据错误直接报错，不混入重复的回退结果。TRACE_STORE_SLOW 保留逐事件重放对照。
搜索、隐藏未成立路径仍须扫描所选范围计数，不能把默认分页速度外推为所有过滤查询速度。

正常运行保留阶段总计时；原生 `build ... --profile` 可开启逐 RUN 的细粒度计时，
会引入额外开销，因此性能验收使用不带该选项的运行。

## 验收边界

2026-10-21 正确性差分验收固定参考 `8c7c48f`（原生重构前的 legacy 展开），
对最终 `1.0.14-native.7` 的 20 个历史正例、11 个历史负例离线验证。
累计完整比较 28,433,087 条事件和 8,526,703 条 OpenCSD 记录；920 组接口查询中
913 组直接相等，7 组为旧时间线未知函数轨道缺陷，均由不依赖项目模块的原始事件核算解释。
另做 140 组时间线独立核算。验收发现并修复候选相位提前退出、异常后待消费返回地址检查丢失、
坏帧诊断绝对偏移遗漏同步前缀三个问题。失败证据和中间版本保留，未将其写成通过。
报告及指纹在本机 `E:/superlinkPRO/docs/validation/20261021-codex-etm-differential-6871ac5-b7d58a26/`，
大体积中间结果在 C 盘同 run-id 验证目录；它们被 Git 忽略，不会随代码自动备份。
本结论仅覆盖清单案例和检查项；样本主要来自 H743，不能外推为所有业务、所有芯片或实时流式正确性。

- 离线测试覆盖 ETMv3／ETMv4、事件展开、分析、窗口、时间线、导航、原始包、
  索引损坏拒绝、宽周期计数、中文路径以及发布失败回滚。
- 源码测试、冻结运行包测试、真实浏览器体验与真机采集分别记录，不能互相替代。
- 当前保留既有二进制路径的包视图限制：原始包字节和分类可用，OpenCSD 的详细包说明文本
  不随主链路生成。manifest 的 packetText.available 明确为 false。
- 完整导出仍需展开大量事件；索引浏览快不代表完整 JSON 导出也同样快。
- 性能结论应读取对应提交的验证报告；达到个别最优值不等于稳定达成门槛。

## 真机恢复后的验收

按 200ms、500ms、1s 逐级采集；先确认完整连续同步和输入字节覆盖，再比较指令、
未知、异常、周期、质量诊断和关键函数。记录采集等待、前端处理、解码、索引、
首屏及交互时间，重复至少三次，并检查峰值内存与派生文件体积。
在上述证据齐备前，不提高默认采集上限，也不宣称具备实时流式解码能力。
