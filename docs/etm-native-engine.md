# ETM 原生链路实验版

本分支把 KVDAT 物理前端、OpenCSD 二进制输出、原生执行事实、完整查询索引与
网页浏览连接起来。目标是减少首屏等待，仍保留质量诊断、谓词未知、异常、
周期、原始包字节和源码定位。它尚不是持续采集和持续解码的流式系统。

## 使用

源码运行时显式设置 `ETM_STORE_WRITE=1`、`ETM_STORE_ENGINE=native`。
便携包可以运行 `etm-bridge.exe --engine native --no-browser`，或者在
`etm.config.json` 中加入 `"engine": "native"`。缺少原生程序或能力不匹配会报错，
不会把回退结果当作原生成功。移除该选项即可恢复原有默认路径。

单次采集默认上限保持 **200ms**。尚未完成连续 500ms／1s 的 H743、akaLinkPro、
Kingst 真机验收；合成规模测试不能替代真机采集。实验包仅在验证目录保存，
不替换原下载包，不发布、不推送。

## 链路与格式

1. 原生物理前端直接读取 KVDAT，完成滤波、DDR 取样、TPIU 解复用，免去 CSV。
2. OpenCSD 写出二进制元素与包，避免逐包格式化文本。
3. 唯一代码范围只反汇编一次；原生构建器同遍产出执行序列、完整分析与 ETMFACT3，
   复用唯一范围的指令编码，并生成热点、PC 单元格和源码区间的数值归约。
4. NumPy 批量构建其余查询表及默认视图；窗口按路径极值和区间归约计算，
   索引表最多四个线程并行压缩，目录顺序和编码保持确定性。
5. 最后原子替换 manifest；异常时保留上一代，并恢复更新前的兼容元数据。

ETMFACT3 的 RUNS 是每 4096 条指令一个的定位锚点，包含原始 RUN 内的 runSkip，
不再为每个动态 RUN 复制一整行事实。事件、周期与路径保持稀疏。
事实静态 ID 使用核心存储首次出现的顺序，不能混用按 PC 排序的传输字典 ID。
临时事实和中间核心副本在发布成功后清理；原始采集文件不修改。

两个字节相位分别保留解析失败状态，到整段收尾时再判定是否恰好一个候选有效。
一个相位遇到坏帧不会终止另一个候选；两者均无效或均有效仍明确拒绝，保留失败诊断。

数值归约的临时格式为 `ETMIDXF1`，绑定同一 native.bin 的 SHA256，验证尺寸与
静态 ID 映射后才参与索引构建。旧辅助程序未声明能力时保留 NumPy 兼容路径；
持久存储仍使用原有查询块 v2，不依赖外置 sidecar。

较大的执行序列使用现有容器压缩标志保存，定位偏移仍指向解压后的序列。
包块保留记录数语义；发布容器直接写到预留好目录的临时文件，避免再次复制整份 payload。
文件 CRC、完整 SHA256、fsync 和 manifest 最终发布仍执行。

无筛选、连续执行序号的区间分页直接按端点计算总行数，避免为计数扫描整段。
搜索、隐藏未成立路径仍使用兼容过滤路径；深处起点还可能有检查点重放成本，
不能把默认分页的速度外推为所有过滤查询的速度。
部分原生记录目前仅有一个执行状态检查点，深处的单事件/调用栈定位仍可能重放数百万条事件；
数值索引中的 4096 指令定位锚点不能直接替代执行状态检查点。这是尚待优化的交互性能限制。

正常运行保留阶段总计时；原生 `build ... --profile` 可开启逐 RUN 的细粒度计时，
会引入额外开销，因此性能验收使用不带该选项的运行。

## 验收边界

- 离线测试覆盖 ETMv3／ETMv4、事件展开、分析、窗口、时间线、导航、原始包、
  索引损坏拒绝、宽周期计数、中文路径以及发布失败回滚。
- 源码测试、冻结运行包测试、真实浏览器体验与真机采集分别记录，不能互相替代。
- 当前保留既有二进制路径的包视图限制：原始包字节和分类可用，OpenCSD 的详细包说明文本
  不随主链路生成。manifest 的 packetText.available 明确为 false。
- 完整导出仍需展开大量事件；索引浏览快不代表完整 JSON 导出也同样快。
- 性能结论应读取对应提交的验证报告；达到个别最优值不等于稳定达成门槛。

## 真机恢复后的验收

按 200ms、500ms、1s 逐级采集；先确认完整连续同步和输入字节覆盖，再比较指令、
未知、异常、周期、质量诊断和关键函数。记录采集等待、前端处理、解码、索引、
首屏及交互时间，重复至少三次，并检查峰值内存与派生文件体积。
在上述证据齐备前，不提高默认采集上限，也不宣称具备实时流式解码能力。
