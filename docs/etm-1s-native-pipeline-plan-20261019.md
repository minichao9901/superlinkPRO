# ETM 1 s 记录与原生快速链路实施方案

版本：1.0｜2026-10-19｜编写：Codex｜执行对象：DeepSeek

本方案由用户要求编写，交由 DeepSeek 实施。当前参考基线为 `7f6c0428f15a565f6f280236d299f513f1e6ee1d`、产品 1.0.13。实施前核对最新主线和工作树；存在更新时记录实际 Tested-Base，不覆盖他人改动。本文件是实施与验收约定，性能目标均须实测，不能当成已经达到的性能。

## 1. 用户目标与本轮边界

首要目标：将现有 H743 单次完整记录能力从 200 ms 提高到 **1 s**，并使保存完成后的解码、基本浏览在可接受时间内完成。

次要目标：建立可以连续分块处理的解码架构，为后续接近 J-Trace + Ozone 的体验打基础。

区分三件事：

1. **1 s 离线记录可用**：采样完成、KVDAT 保存后快速处理，网页可浏览完整 1 s。
2. **主机增量处理**：输入按块进入时持续解码、统计，已有完整块可供浏览。
3. **采集中实时分析**：采集设备能在采样过程中提供数据，整个系统吞吐持续超过输入速率。

本轮必须完成第 1 项，并形成第 2 项的可测实现。第 3 项不作为本轮交付前提；现有 LA 若只能采完再 `save-data`，不得把主机分块处理称为采集中实时流。

不改 USB 传输硬件、不换探针、不修改目标业务固件来减少 trace、不通过删掉未知状态/中断/周期数据达成绩效。ETMv3、既有 CSV/BIN/记录包继续可读；1 s 新能力先限定在完成验收的 H743 配置。

## 2. 已有事实与可复用证据

### 2.1 当前主要成本

当前链路：

```text
KVDAT → Python/NumPy 取样 → Python TPIU 解复用
      → OpenCSD 输出 native.jsonl
      → Python 逐指令展开、统计、events.jsonl + browse-columns.tsv
      → 再次扫描构建 SQLite → Web
```

200 ms H743 约 368～386 万条路径指令记录。已有完整流程在不同运行中为 60～107 s，不能承诺第二次必定 67 s。区间查询已明显提速，完整窗口约 1 s，缓存后约几十毫秒；新的优化重点是**首次处理新输入**。

boundary 样本的实际文件体积：

| 内容 | 字节数 |
|---|---:|
| ETM 原始流 | 384,518 |
| events.jsonl | 1,769,496,802 |
| browse-columns.tsv | 823,953,908 |
| browse-v3.sqlite | 308,371,456 |

相同负载线性延伸至 1 s，仅 events 文本就约 8.85 GB。需要改变保存和查询模型，不能只调整缓存或把现有文本生成循环翻译成 C++。

### 2.2 OpenCSD 核心隔离测速

同一 OpenCSD 1.8.3、相同 `-O2`、输入/镜像/配置：

| 200 ms 输入 | 原文本输出一次 | 只做解码及计数，三次中位数 |
|---|---:|---:|
| steady | 3.343 s | 0.180 s |
| boundary | 3.303 s | 0.188 s |

计数版关闭了元素和包的字符串格式化/输出，保留了 OpenCSD 解码。元素数、包数、包字节和指令范围 payload 总数一致，处理完整、错误码为零。一次启动波动 0.373 s 也保留。

**该诊断不是可上线的完整解码器**：没有保存逐元素语义，也没有质量核算、调用栈、周期归因、索引或页面。不得直接拿诊断版替换生产程序，或据此声称已经实时。

## 3. 验收目标与时间口径

### 3.1 第一档：1 s 可用，必须验收

以下是当前 H743、相似负载、500 MSa/s 配置下的**工程验收目标**，不是任意负载保证：

| 指标 | 目标 | 计时边界 |
|---|---:|---|
| 200 ms 新输入完整处理 | ≤3 s | KVDAT 完整可读 → 完整二进制记录、统计、必要索引就绪 |
| 1 s 新输入完整处理 | ≤10 s，争取 5 s | 同上；不计 LA 上传/保存及可选文本导出 |
| 首次打开已处理记录 | ≤1 s | HTTP 请求开始 → 概览、首 150 行、默认轨迹图响应完成 |
| 1 s 全区间首次统计 | ≤1 s | 冷窗口计算，含 HTTP 传输与 JSON 解析另列 |
| 已缓存相同区间 | ≤100 ms | HTTP 请求至解析完成 |
| 局部定位/翻页/导航 | P95 ≤200 ms | 自动化查询序列；单列冷启动 |
| 内存 | 1 s 全流程峰值 RSS 总和 ≤2 GiB | 包括子进程，不只记录 Python RSS |
| 新派生数据体积 | 代表性 1 s 样本 ≤512 MiB | 不含 KVDAT/原始流/ELF/可选完整导出；报告总落盘量 |

首屏不得只是展示一个旧摘要：从整段取最后一页、末端 PC 定位和跨段窗口均应可用。允许提前展示明确标记的进度预览，但另列 `previewReady`，不能替代完整就绪指标。

未达标时保留默认 200 ms 和实验开关，交付实际分项结果。不得为了通过而把必需索引/统计挪到计时外，也不得静默减少数据或筛掉慢样本。

### 3.2 第二档：主机实时潜力，独立报告

必须保留状态地连续输入，测真实的区间重建和必要统计，不使用计数空回调冒充完整处理。报告：输入 ETM MB/s、重建路径记录/s、每阶段服务率、队列峰值/趋势、CPU、RSS、磁盘写入量。

参考当前负载约需处理 1,840～1,930 万条路径记录/s。真正实时要求持续处理速度大于输入速度，并有余量；建议目标 ≥1.5 倍余量。0.18 s/200 ms 的空回调仅有少量余量，并未达到此验收。

先做保留解码状态的文件回放、无节流饱和测试和有节流持续测试。拼接多个独立 capture 只能用于带显式会话复位的压力测试，不能冒充一段连续真机 trace。

## 4. 最终数据流与职责

```text
KVDAT（完整保存后，先作为文件输入）
  ↓ 分块读取、严格布局校验
原生脉冲滤波 / DDR 取样 / 字节相位验证 / TPIU 解复用
  ↓ 有界批次、完整质量与偏移信息
OpenCSD 长寿命解码树
  ↓ 结构化元素，常规路径不生成说明文字
原生执行区间构建器 + 调用/异常状态机 + 增量统计
  ↓
版本化二进制记录 + 静态代码字典 + 稀疏/分层索引 + 摘要
  ↓
Python 查询适配层（必要时调用原生查询）
  ↓ 仅当前页面/区间 JSON
现有 Web 执行流、源码、调用栈、轨迹图

旁路：原始 KVDAT/ETM、ELF/配置/源码快照 → 按需完整 JSONL/CSV 导出
```

Python 保留任务管理、Flask API、设备流程编排、兼容与导出入口。新热路径使用现有 C++/OpenCSD 工具链，优先外部原生程序，避免第一阶段额外引入扩展 ABI 和大量打包依赖。

先分阶段落地，最终融合同一次解码与区间写入，避免永久保留“二进制元素文件 → 再完整读取 → 再生成另一份二进制”的重复流水。

## 5. 存储契约：先写规范，再实现

建议新格式命名 `trace-store v1`，与现有 SQLite v7、streamed schema 2/3 区分。具体文件名可调整，语义与兼容要求不能省略。P1 提交完整字段表、读写示例及版本规则。

### 5.1 静态字典

- 每个唯一指令 PC 存一份机器码、长度、反汇编、函数 ID、文件 ID、行号、流类型与谓词信息。
- 以 ELF/机器码内容与相关配置指纹标识字典；保留重复函数名、同名文件、Unicode 路径、内联位置等既有行为。
- 建立“区间/基本块 ID → 有序指令描述 ID 列表”，不要假设所有区间只属于一个函数或源码行。
- 对非连续内存、Thumb 指令宽度、不可访问地址保留错误和边界语义；不能补猜机器码。

### 5.2 动态区间与稀有事件

常规动态记录引用静态区间，保存至少：逻辑 seq 起点/长度、trace 源偏移、有效执行范围、末指令执行条件、内部未知谓词覆盖、周期及其归属、调用状态引用。异常、同步、缺口、上下文、未知源等采用显式事件类型。

关键约束：

- **逻辑 seq 与旧网页一致**：它包括旧实现实际暴露的指令及边界事件，不等于原生元素编号或物理时间。
- 除末指令外，区间内部也可能有 IT 条件未知；不能把全部内部指令标为 executed。
- 一个原生 range 不保证等于一个可直接聚合的基本块；必要时按调用/返回、函数边界、谓词状态、周期锚点切分。
- 保留范围末指令的周期记账和跨元素 pending-tail 归因；不能均匀分摊周期或改变 cycleSpan。
- 调用栈以父节点 ID/帧 ID 等结构共享；每条指令不重复保存字符串路径。
- 初始调用栈未知、尾调用、递归、异常嵌套、tail chaining、异常返回地址不匹配的失效规则，与参考实现对照。
- RLE/压缩只有在能完整恢复每次状态、周期、源偏移和序号时使用；第一版不做会丢信息的合并。

### 5.3 原生元素和包信息

P2 可先落结构化二进制中间文件，必须覆盖当前回调实际使用的字段：type、offset、trace ID、地址、ISA、flags、payload、lastExecuted/Conditional/Type/Subtype、周期/时间戳及其存在位等。宽度按 OpenCSD API 定义，不用未经证明的 32 位截断。

包记录保留源偏移、字节长度/类型和异常信息，原始字节可引用 ETM 流。正常运行不调用每包 `ocsd_pkt_str()`、每元素 `ocsd_gen_elem_str()`；在需要展示/导出说明时，按同版本配置重放或局部生成。只有证明一致的文本才缓存；不可凭简化枚举重写诊断含义。

P1 必须另外列出 ETMv3/4 包说明实际依赖的规范化字段，而不是只存 type/offset 后假定可以无状态恢复全文。必要的解包上下文/字段在构建时保存，异常诊断允许存稀有字符串。正常翻页不能每次从头完整重放 1 s trace；重放可以用于离线兼容导出或一次性缓存构建，其成本另列。

原始输入+配置+ELF+解码库版本是可重放依据。若某字段无法可靠从原始输入和索引恢复，就在二进制记录中显式保存。质量核算仍须具备完整分母、offset 和错误来源。

### 5.4 版本、完整性与安全读取

- 明确 magic、schemaVersion、字节序、记录类型、记录长度/块长度、计数、有效范围、必需 feature flags。
- seq、文件偏移、累计数量/周期使用足够宽的整数；建议累计与偏移用 64 位。所有长度乘加先做溢出检查。
- 禁止直接把编译器原生结构体布局当持久协议；显式编码，定义 padding/对齐，并测试大小端处理或明确拒绝。
- 块带校验和；输入、ELF、配置、软件处理参数用强指纹绑定。记录编解码引擎/格式版本。
- 截断、未知强制字段、损坏索引、越界 ID、巨量分配请求必须拒绝或明确从原始流重建，不返回拼凑结果。
- 生成到独立 generation/临时目录，完整成功后原子发布 manifest；Windows 下注意 mmap/打开句柄阻碍替换。
- 中止/崩溃留下的临时生成物不得被当成完整记录；上一代完整结果与新结果不混读。
- 校验策略记录清楚：构建时计算完整输入指纹，读取涉及块时验证其校验；不得仅因 size/mtime 相同就认定原始输入未变。兼容现有输入校验承诺。

## 6. 查询与网页兼容

### 6.1 查询层

新增存储适配器，例如 `TraceStore`，让 `browse_store()` 按 manifest 选择后端。不要将老 `RecordStore` 全部重写后才开始验收。

原 API 的以下操作要逐项支持：

- `overview`、`page`、`event/<seq>`、`navigate`、`timeline`、`window`、`issues`、源码与记录导出。
- 首页/末页、PC 定位、源位置/调用/返回/异常/未知导航。
- 搜索、隐藏未成立路径、区间裁剪、默认排序与稳定的同权重顺序。
- 任意区间的首尾只包含半个动态块时，正确裁剪计数、周期、调用与 marker；不能套用整块汇总。

稀疏 seq 索引定位到动态记录和局部指令，按需展开通常 150 行。函数/源码映射按静态字典查找，不再次逐指令查 ELF。全文搜索先找静态字典 ID，再查动态出现位置；动态事件文字单独索引。

整段和大窗口用分层汇总/区间前缀与动态块聚合；精确边界单独处理。每次窗口扫 1,900 万条逻辑指令属于退化，不作为新默认实现。

调用树/轨迹图至少保留现有函数、路径、未知、未成立、异常及周期语义。路径共同前缀、mixed 标记、桶边界与事件顺序必须对照。统计使用整数，避免浮点大数累计和溢出。

### 6.2 默认路径与导出

完整 `events.jsonl`、`native.jsonl`、`browse-columns.tsv` 不再是新格式记录浏览的前置产物。

既有 JSONL 记录继续读；新记录的 JSONL/CSV/HTML/简化源码按用户请求生成，可流式输出并支持取消。完整导出耗时与字节数单列，不纳入日常浏览承诺，也不能说它不占时间。

`.etmrecord` 至少包含原始证据、配置、ELF/来源信息和新格式必要文件，支持自导出后在另一独立目录导入、重新解码、浏览和导出。不得只导出一个本机路径引用。

旧版软件不能读取的新包要明确标识最低版本；不得伪装旧 schema。保留“兼容旧版导出”路径或提供清晰错误。旧 longWindow/schema3 记录继续读取，不为了 1 s 功能恢复多个独立采集拼接的方案。

### 6.3 UI 与任务状态

- 沿用执行流/火焰图交互，不把处理引擎选择等实现细节放到普通用户流程。
- 区分采样、保存、取样/解复用、解码、发布、可选导出；进度有分母才显示百分比，否则显示阶段/已处理量。
- settings 关闭时也能看见正在处理和错误状态。
- 快速连续缩放/切换时，旧请求结果不能覆盖最新选择；控制重复请求及后台计算。
- 预览标注“处理中/范围未完整”；最终完整状态与原始证据校验结果关联。

## 7. 原生物理前端与分块状态

先严格移植现有语义，再做有证据的优化。KVDAT 的 3.6.x 已验证布局、初始电平、触发位置、结束哨兵、边沿标志与顺序检查继续保留。

建议使用按通道的有界读取游标/分块缓冲，按时钟边沿取数据电平，避免构造全量浮点时间数组。是否用 sample tick 替代浮点计算，必须证明取样点和滤波边界与当前参考一致；记录 rate/fraction/glitch 参数和选择的字节相位。

相位选择须保持现有“整段数据只能有一个有效候选”的语义。可并行维护候选验证状态、在严格排除一个候选后选择；不能凭短前缀看似同步就猜相位。必要时缓冲或回放前缀，两个候选最终都有效或都无效时明确失败。

跨块必须携带：

- 上个电平、前后边沿、尚未判定的窄脉冲；滤波不能在块边界误删完整电平。
- 上个半周期、取样点、DDR nibble/未成字节、字节相位候选。
- TPIU FSYNC/HSYNC 前缀残片、partial frame、current trace ID、未知源和尾部残片计数。
- OpenCSD 状态、回压状态、未结束元素、pending-tail 周期/执行状态。
- 调用/异常栈、逻辑 seq、累计质量与统计。

处理状态跨块连续，只有会话真正结束才发送 EOT。不得把每块尾部当捕获边界，也不得每块重新寻找同步后静默丢前缀。针对每个可能边界附近做分块等价测试。

流水线采用有界队列和明确的错误传播；消费跟不上时要保留原始输入并显式报告积压/失败。对于将来的实时输入，不能靠无限增长内存或静默丢块维持“实时”。优先顺序消费同一条 ETM 流；不要任意多线程解码其不同片段。线程/进程并行用于独立取样、写盘、查询等阶段，并实测收益。

## 8. 分阶段实施与交付门槛

### P0：固定基线、基准与阻塞问题

产物：仓库内可复用 benchmark/compare 入口、输入清单、不可变原始结果、实际环境信息。

- 同样输入、配置、功能和构建模式做旧/新 A/B；交错运行至少各 3 次，报告全部样本、中位数、范围；启动/缓存条件分列。
- 分项：LA save、KVDAT read/validate、filter/DDR、TPIU、ELF/反汇编字典、OpenCSD、区间/调用/周期、统计、持久化/索引、overview/page/timeline/window、浏览器。
- 记录墙钟、进程 CPU、峰值 RSS 总和、各文件字节数、输入/工具哈希、构建参数。计时不包含验证扫描的开销，验证另列。
