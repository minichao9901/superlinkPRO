# ETM 1 s实验长窗发布说明（2026-10-23）

用户决定从 `1.0.14-native.13` 起开放 Web 单次最长1 s、最多5亿采样点。
这一决定替代此前“默认200 ms、等待全部性能门禁通过再开放”的产品限制；
不表示此前所有验收指标均已达标。默认时长仍为10 ms，用户可自行填写至1000 ms。

本地服务 `/api/capabilities` 决定页面实际上限。网页遇旧服务时继续采用旧服务的上限，
旧服务缺少能力接口时回退200 ms。升级时需退出旧EXE，完整解压新包后重新启动。
完整原生前端、OpenCSD、TraceStore、导出、筛选和同固件准备缓存默认继续开启。

## 实测与限制

- H743 CPU60 / TRACECLK20 MHz：200/500/1000 ms各三次持续banner/echo采集；
  1 s约1836万条指令，完整处理约14.1～14.4秒，不含采集、回传和保存。
- TRACECLK30 MHz：本轮500MSa/s请求1 s，实际仅926.77 ms；严格帧检查通过，
  约1702万指令、处理15.22秒。尚不能宣称30 MHz完整1 s稳定通过。
- 高频连续跳变可能提前耗尽LA压缩存储。服务保存实际采样深度；不足请求窗口时明确提示，
  原始波形保留并继续解码**实际窗口**。报告显示实际采集时长，不能用请求参数证明录满。
- 末尾截断、初始未同步、IT条件未知继续保留；没有通过放宽解码器的帧检查来扩大上限。
- 首次打开部分导航索引仍可能约0.48秒；预热后通常几十毫秒。性能门禁尚未全部满足。

真机报告分别见 `docs/validation/20261023-codex-h743-live-19d7d53-db17fe80/report.md`
和 `docs/validation/20261023-215916-codex-h743-30mhz-1s-4cf33e/report.md`。
同一仓库中的旧清单、历史测试报告和200 ms数据仍按当时条件解释，不追改历史结论。
