## 1. 当前决定与接手原则

用户的核心目标是：用 Kingst LA 采集 STM32H7B0 的并行 ETM 信号，结合匹配 ELF/DWARF，还原可信的机器码路径和源码执行流，并提供 Web 分析页面。

已按用户要求完成并固定 **CPU 70 MHz / 物理 TRACECLK 35 MHz 稳定基准 v1**。频率优化暂停，没有安排自动高频实验。后续重点转向执行流分析。

- 独立工作目录：`E:\web-etm-trace`。
- 主工具目录：`E:\web-serial-rtt-tools`，**目前仍未接入**。用户此前明确要求先完善独立工具。
- 原 SPI 工程：`E:\Share\github\STM32H7xx_Develop\App_SPI_H7B0`；原工程未修改。
- 本轮结束时板上是封存的 70/35 MHz 固件，业务运行正常；采集前 trace 设置已恢复，原生 SWD 验收连接已释放。
- 下次先用已有记录做离线工作，无需先烧录、复位或重新采集。较大的新需求先列出范围与步骤，等待用户确认。
- 不覆盖 v1 封存文件，不把旧 8/4 MHz ELF 或实验档 ELF 用于当前板上程序。

## 2. 硬件与固定参数

| 项目 | 已确认配置 |
|---|---|
| MCU | STM32H7B0，Cortex-M7；DEV_ID `0x480`，CPUID `0x411fc271` |
| 晶振与供电 | HSE 25 MHz，LDO |
| 稳定时钟 | CPU 70 MHz，HCLK 35 MHz，物理 TRACECLK 35 MHz |
| LA | Kingst MIPI16，500 MSa/s/ch；不能直接把 LA5016 的规格当作本机额定上限 |
| 接线 | CH0=PE2/TRACECLK；CH1～4=PE3～PE6/TRACED0～3；共地 |
| LA 参数 | 500 MSa/s，阈值 1.65 V，半周期取样位置 0.25 |
| GPIO | AF0、推挽、无上下拉，驱动速度档 3 |
| 毛刺过滤 | 采集档案确认 CH0～4 均为 1 点，即 2 ns；其他通道关闭 |
| ETM | 4 位 DDR，Trace ID 2，CONFIGR=1；返回栈压缩和周期计数关闭 |
| SPI 业务 | SPI2 内核 200 MHz、分频 /4；轮询发送 100 字节，PC8 标记，保留 SysTick/MPU/缓存/RTT/UART |
| SWD 探针 | akaLinkPro CMSIS-DAP，VID/PID `0D28:0204`，序列号 `8F538633E6AEC4CA8ABB6A36FEBB1AC2` |

35 MHz 是物理时钟；DDR 每半周期传输一次，符号率为 70 M 次/秒。500 MSa/s 对应 2 ns 采样间隔。CPU/TRACECLK 比例不能单独证明任意业务无损。

两份采集在半周期 0.10、0.20、0.25、0.30、0.40 的位置均得到各自相同的 ETM 字节流。所选稳定窗约 4.2 ns，0.25 处最小数字数据跳变距离约 2.5 ns。靠近数据转换区的位置仍可产生错误或不同字节流，固定 0.25，不任意调整。

10 ms 窗口保留 2 字节同步前数据和 14 字节不完整尾帧；末尾还有未闭合发送，已见 3 次字节写入，未计为完整发送。

“全量”目前指**窗口内无地址过滤的业务指令 trace**：包含整个业务控制流，区别于 PC 抽样。它没有包含上电启动全过程，不能宣称每条条件指令的执行状态全部确定，也不能证明所有程序或无限时长都绝不丢失。

## 5. 配置分工与操作陷阱

**目标固件**负责晶振/供电/VOS、Flash 延迟、PLL P/R、CPU/HCLK、外设/SysTick 时钟、缓存/MPU和业务。普通 SPI 固件不会自行打开 ETM。

**Web/SWD**负责回读能力与时钟、完整 Flash/ELF 校验、trace 门控/引脚复用/CoreSight 路由、Trace ID/压缩选项、暂停/继续/业务复位及设置恢复。HSE 输入仅用于计算，网页不写共享 PLL 或 CPU 时钟。

**LA/本地服务**负责采样率、阈值、深度、触发、采集起止、档案保存和解码。滤波能力说明见 [毛刺过滤脚本说明](../tools/la/毛刺滤波使用说明.md)。

必须保留以下经验：

1. **CFG bit0 是 RES1，不是 INSTP0。** 不能把 CONFIGR=1 解读为某个新增跟踪功能。
2. **滤波没有公开 Socket 实时设置接口。** 新增 `glitch-filter-info` 从 KVDAT 读真实设置/采样率；`glitch-filter-preset` 生成副本或在 VIS 正常退出后备份并写启动预设。预设启动加载尚未经过本轮实机重启验收。
3. 本次滤波保留模式为“下次启动清除”；重启 VIS 后不要假设 1 点设置仍在。磁盘 `vis.config` 可能落后于运行中 GUI，以新采集档案快照为证据。
4. 本轮启用滤波的 KVDAT 与 CSV 边沿相同，不能宣称其中保留了滤波前数据。滤波不能恢复漏采边沿或提高输入带宽。
5. CoreSight FIFO 曾出现未完成刷新；遇到超时要保留状态，不能直接强关 FIFO 后改 PLL/烧录。已有关闭顺序是下游保持接收、FIFO 启用时 flush/stop、等 Ready、再清 CTL。
6. 复位入口暂停实验曾使 SWD 内存访问失效；启动入口选项已禁用。不要直接恢复该选项或把业务捕获改称启动全程捕获。
7. 探针重新插拔后，旧 pyOCD 会话可能产生 NAK/USB I/O 错误。确认占用进程、释放旧会话后重新连接；不要默认故障来自 ETM。探针在 Bulk V2 枚举失败后回退 HID 时曾挂起，应先检查实际接口。
8. 原生验收服务和浏览器不能同时独占探针。服务结束应释放连接，避免下一次网页连接失败。重启服务时按端口核对进程，不能硬编码旧 PID 或批量杀 Python。

140 MHz CPU / 70 MHz trace 在 1 点滤波下仍未通过完整帧校验；不同 GPIO 驱动速度和相位也失败。280 MHz 的 70/56 MHz 输出曾失败；46.667 MHz 相位敏感；280/35 MHz 曾通过当前业务验证。以上是当前接线和软件条件的实验结果，不是 MIPI16 的绝对频率上限，现阶段均不再优化。

## 6. 已知能力边界

- **条件指令精度**：IT 非分支条件指令缺少条件结果，保守标记 `executed=None` / unknown，不以当前 RAM 或未证实的标志位补猜。OpenCSD 1.8.3 完整路径解码器对启用条件追踪的配置存在不支持检查；不能只打开 ETM COND 就宣称问题解决。
- **调用栈**：已有重建和灰色未知祖先；缺口处断栈。复杂函数指针、递归、尾调用、嵌套中断、异常尾链、HardFault、优化/内联与 RTOS 还需扩大真实验收。
- **性能数据**：火焰图按路径记录数加权，包括未成立/未知状态，不能称耗时图；调用次数不等于精确每秒调用率。没有逐指令时间轴。
- **变量**：本页未实现变量面板。H7B0 当前 instruction-only trace 不能直接提供全部历史寄存器/内存值；暂停后的当前值必须与历史执行位置分开。
- **覆盖率**：源码映射率不是覆盖率。尚未完成指令/基本块/分支/函数/文件覆盖的统一定义和展示。
- **长记录规模**：10 ms 的 `decoded.json` 约 272 MB。当前 API 一次载入整个结果，浏览器已能展示这份记录，但默认用 1 ms 预览。扩大窗口前应优先改进存储和按需加载。
- **连续采集**：当前是有限窗口采完后导出和解码，未验收无限时长流式采集或 J-Trace 类持续带宽。

## 7. 后续事项与建议顺序

建议下一轮先做 **执行流导航 + 准确性回归**，继续使用封存记录，不触碰频率和启动入口。

### 第一优先级：把执行流做得可信、好用

1. **建立精度回归矩阵。** 先用现有 1/10 ms 两份基准核对包字节、分支、调用和未知数量；再设计独立预期路径的专用固件，覆盖 IT、函数指针、递归、尾调用、中断嵌套和损坏/截断输入。新测试固件另建版本，保持 70/35 时钟。不要只用解码器自己的输出当预期结果。
2. **历史导航。** 增加上一/下一指令、上一/下一源码位置、跳到调用/返回/异常、指定序号/PC 跳转，以及选中位置的调用栈面板。搜索后仍保留原始顺序和区段边界，源码同一行对应多条指令时允许展开查看机器码。
3. **区段可信度。** 将初始化、失同步、overflow、尾部截断和未知条件定位到具体字节/记录区间；区分路径已知与执行状态已知。导出保留同样的标记。
4. **解决长记录加载。** 将元数据/汇总与详细事件分离，提供事件分页、序号/PC索引和函数范围查询；大 JSON 按需读取或转为有索引的分块/SQLite 数据。保留原始证据和记录格式兼容性，先验收 10 ms 再扩窗口。

### 第二优先级：扩大核心分析

- **条件追踪专项**：先检查 ETM 能力与 OpenCSD 支持边界，做最小 IT 示例验证原始包与路径语义。评估更新/扩展解码器的成本，再决定是否实现；完成前保持未知标记，不能靠关闭编译优化当通用解决方案。
- **调用图、选区统计与覆盖率**：仅在可信区段上统计实际调用边与基本块/分支；未观测到不直接等于没执行，必要时给覆盖下界。允许用户选一段业务范围做比较。
- **异常与故障回溯**：在真实验收后增加嵌套层级、异常进入/返回及故障前历史定位；初期用离线记录，避免把未经验证的复位入口再引入主流程。

### 后续可选项目

- **时间分析**：先确定周期计数/时间戳的可用性和边界，再显示有依据的区间时间；不能均分 LA 窗口给每条指令。耗时火焰图和每秒调用率必须明确时间依据。
- **当前变量/局部变量**：复用主工具 `app/dbg/locals.js`、`cfi.js`、`backtrace.js` 等已有基础，暂停时读取寄存器/内存并求值 DWARF 位置描述；优化掉或不可恢复的值显示不可用。单独面板标明“当前暂停状态”。
- **历史变量事件**：若用户需要，另设计明确时间/序号关联的软件日志或快照；这是额外采集通道，不能把当前读数贴到历史 PC 上。
- **主工具接入**：用户重新确认后再做。沿用共享 ProbeBus、设备连接和 SWO 的配置分工；先讨论 Python/OpenCSD 本地服务的启动、依赖及页面路由，不直接复制一套独立连接占用探针。
- **频率与长期流式采集**：继续暂停，待用户明确重新启动。70/35 的稳定基准不可被新实验覆盖。
