# ETM 复用 SourceStore

2026-10-11，按用户要求统一源码目录处理。

## 模块关系

ETM 页面导入 `/app/shared/dbg/source.js` 的 `SourceStore`。独立服务优先直接提供 `E:/web-serial-rtt-tools/app/dbg/source.js`，因此当前与调试页、SWO 页使用同一个源模块文件。独立工程同时保留字节一致的副本 `web/app/shared/dbg/source.js`；主工具目录不存在时使用该副本，便于独立运行。

主工具文件没有修改。之后集成进入主工具时，可直接使用主工具的模块路径。

原独立的 `matchSourceFiles` 匹配实现和 `source-selection.js` 已删除。ETM 的 `source-snapshot.js` 仅调用 `SourceStore.read()` 收集 ELF 所需文本，负责分批保存快照，不实现目录授权或路径匹配。

## 操作

- “选择源码目录…”优先使用 `SourceStore.pick()` 的目录句柄授权，与调试页一致。ELF 路径清单先交给模块，按所需路径打开文件；完全未匹配时保留 SourceStore 的目录扫描兜底。
- “选择源码文件夹（兼容模式）…”采用 `webkitdirectory`，经 `SourceStore.indexFileList()` 建立索引，与 SWO 页一致。不支持目录句柄 API 的浏览器，普通按钮自动使用此兼容路径。
- 路径规范化、后缀匹配、唯一同名兜底、读取缓存、目录切换检查以及 2 MiB 单文件读取上限，均来自共享模块。
- 索引不代表内容读取。当前 SDK 的兼容路径按 ELF 清单索引到 58 个候选文件（包含同名兜底候选），实际只调用 read 读取 22 个所需文件，保存 1.09 MiB 的本地快照。
- ETM 为独立记录保存源码快照，随后采集请求只携带快照编号；这一层仍由 ETM 负责。历史执行流继续使用记录自身快照，不依赖浏览器目录句柄。
- 新 ELF 失效旧快照；重新选择目录后生成与新 ELF 绑定的快照。目录取消不覆盖之前已经保存的快照。

## 验收

- 50 项 Python、27 项 JavaScript 测试通过。包含共享模块 HTTP 内容与主工具原文件一致、便携副本字节一致，以及 SourceStore 的延迟读取、同名歧义、真实大目录索引、目录句柄仅打开 ELF 引用路径、大小限制和缓存。
- 浏览器通过兼容目录入口选取原 3,433 文件目录，显示“匹配 22 / 22 个文件 · 1.09 MiB · 已保存本地快照”，无浏览器错误。
- 原生目录句柄路径复用未修改的 SourceStore.pick，经过模拟目录句柄的按需索引测试；此次没有自动操控外部 Chrome 的原生目录授权对话框。
- 本次未操作目标板、SWD 或 LA，未改变固件或频率。
