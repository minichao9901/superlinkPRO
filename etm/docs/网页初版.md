# ETM 执行轨迹网页初版

入口：**http://127.0.0.1:8766**。本次已启动本地服务并打开页面，默认显示 H7B0 的真实记录。
下次使用可在项目根目录双击 `start-web.bat`，或运行 `pwsh -File start-web.ps1`。

## 已实现

- SWD 探针连接、软件复位并暂停、暂停/继续。
- H7B0 四位并行 ETM 配置、trace ID、返回栈压缩、周期计数、配置读取与关键配置回读。
- KingstVIS Socket API 联动，设置采样率、时长、阈值、通道；开始/停止采集，保存实际窗口的 CSV/KVData。
- 采集后自动解码与单独解码；导入原始 CSV、已解复用的 ETM BIN 或自包含 `.etmrecord`。
- OpenCSD 1.8.3 处理当前 H7B0 配置的 ETMv4 包并恢复指令范围，Capstone 展开 Thumb/Thumb-2 指令，ELF 符号与 DWARF 源码映射。并非所有 ETMv4 可选特性均已支持，详见 [准确性审计](Trace完整性与功能差距审计.md)。
- 执行顺序、条件未成立分支、ETMv4 包、函数统计、点击指令定位源码。
- 简化源码 `.c`、完整源码执行流 `.c`、CSV、JSON、原始数据、KVData 和记录包导出。
- 窄窗口下隐藏采集侧栏，点击顶部“采集设置”展开；桌面窗口同时展示指令与源码。

## 初次使用

1. 页面默认加载 500 MSa/s 实测，可直接浏览源码、查看包与导出。
2. LA 使用前打开 KingstVIS，开启 Socket API（23367）。CH0~4 接 PE2~6，接 GND。
3. 已有固件正在输出 trace 时，可以不连 SWD，直接“开始采集”。
4. SWD 联动：用支持 WebUSB 的桌面 Chrome/Edge 打开入口，在浏览器设备选择框选择 akaLinkPro/CMSIS-DAP；使用与目标匹配的 ELF，勾选“与 SWD 联动”。
5. 联动会暂停目标、逐字节核对 ELF 的代码段、应用 ETM 设置，再让 LA 等待 D0 下降沿；收到后台等待状态后继续目标。
6. 采集完成会保存原始数据。取消“自动解码”可稍后再解码；“停止”会终止采集，并保存实际采集到的短窗口。

KingstVIS 的 `start` 会阻塞；`stop` 在某些版本会吞掉响应甚至中止连接。本地服务在停止后换新连接，并以允许设置触发条件的设备空闲回读确认停止，随后导出；页面不会仅凭按钮状态宣称硬件已停止。

## 与板上代码匹配的 ELF

本轮读取目标 Flash 后确认，板上仍运行第一轮构建版本。`firmware/stm32h7b0_etm/fw.elf` 是之后调整 TPIU 初始化顺序的版本，两者机器码不同。

已经在 **`firmware/stm32h7b0_etm_board_v1`** 重建板上版本，完整 **7672 字节 Flash 镜像逐字节一致，差异 0**；网页默认使用这份 ELF。无需重新烧录即可测试当前板子。
它保留原初始化顺序，HAL 的 `__FILE__` 通过宏路径映射保持与板上镜像一致，DWARF 仍指向独立保留的旧版源文件。

- Flash 镜像 SHA-256：`c967204e9da3fb02a30b96cad4364f033325494f2e0aa836e83f2dcdada51ce9`
- 匹配 ELF SHA-256：`b5bc0f45126988fe4da3f8d93cf5a9c2aaa01826f04b8d472bd6eb8014a5a3b0`
- 实际 ETM：IDR0=`0x080006E1`，IDR1=`0x4100F401`，IDR2=4，IDR8=1，IDR12=1，CONFIGR 的固定字段读为 1。

代码版本改变后，使用新 ELF 与新采集记录；不要将旧采集强行配上新版本 ELF。

|---|---:|---:|
| ETMv4 包 | 1058 | 912 |
| 恢复指令范围 | 2951 | 2426 |
| 指令记录 | 10753 | 8798 |
| 映射到源码 | 10753 | 8798 |
| SysTick 进入 / 返回 | 6 / 6 | 5 / 5 |
| OpenCSD 错误 | 0 | 0 |

独立验收检查下一条 PC 是否符合直接分支目标/顺序落点，每次完整 `trace_workload` 是否有八次交替函数调用，以及异常号 15 与返回数是否一致。

真实 SWD 控制模块 + LA 联动验收：

- 默认配置新采集恢复 **17229 条**指令记录，全部映射，10 次 SysTick。
- 返回栈压缩 + 周期计数新采集恢复 **17296 条**指令记录，全部映射；识别 Cycle Count F1/F2/F3 等包。
- 软件复位后确实处于暂停，继续后有实际 trace。
- 提前停止完成，保存的是实际短窗口，任务结束时恢复目标运行和默认 ETM 配置。

网页真实按钮已经验证 LA 连接、直接采集并自动解码、函数/包视图、源码点击定位、下载和记录包重新导入。浏览器首次 USB 设备选择需要用户完成；SWD 控制模块本身通过同一 `target.js` 在真实探针/目标上的适配测试验证，测试适配器没有替换寄存器逻辑。

离线测试 **13 项通过**，覆盖物理采样、中文 CSV、TPIU 辅助位/数据源切换、已知程序路径、源码流保序、记录保存重载和导出。

证据：`docs/validation/2026-10-11-target-readback.json`、`2026-10-11-live-controls.json`，以及 `decoded/500m`、`decoded/100m` 和 `records/` 中的原始/解码数据。

## 当前边界

- 初版适配 H7B0/当前板子的四位并行 trace，没有承诺所有 STM32/所有封装。
- 存在初始失同步与窗口末尾不完整数据，输出明确保留这些边界；不会补造缺口内代码路径。
- 程序流可恢复，不能仅凭它恢复变量值或每条指令的绝对执行时间。周期计数在包/结构化数据中保留，未伪造时间轴。
- 源码执行流是按顺序的源码片段记录，不是可编译程序；连续相同位置可合并，非连续返回和缺口不合并。
- 页面按 150 条分页显示，导出遍历完整解码结果。初版展开上限为 200 万条，超过时明确拒绝而不输出截断的“完整”结果。
