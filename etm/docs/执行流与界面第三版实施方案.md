# 执行流与界面第三版实施方案

2026-10-11。依据本轮用户需求整理，待确认后实施。继续在 `E:\web-etm-trace` 完善独立工具，固定 CPU70/TRACECLK35 稳定基准 v1，暂停频率优化，不覆盖封存文件，暂不接入主工具。

## 本轮交付

1. 执行流可信度与回归：保留条件状态未知和捕获边界，显示区段与原因；以封存 1/10 ms 记录核对包覆盖、分支和 SPI 结构，并增加复杂调用、异常及损坏输入的独立预期用例。需要新增真机测试程序时另建版本，保持 70/35。
2. 历史导航：上一/下一指令、源码位置、调用/返回/异常、按序号或 PC 定位；选中位置同步显示源码、机器码及历史调用栈。历史栈与当前暂停目标的状态分别标识。
3. 长记录：拆分汇总与详细事件 API，加入分页、索引和按需查询，避免每次下载整个约 272 MB JSON。保留旧记录及导入导出兼容性。
4. 左侧侧栏按责任分为四个 Tab；右侧以执行流与源码为主要工作区域，辅助统计缩为状态条和折叠面板。
5. ELF 函数列表、符号搜索与硬件断点，支持从选定函数暂停位置配置 ETM，再联动 LA 开始执行和采集。

## 左侧 Tab 分工

| Tab | 内容 | 操作责任 |
|---|---|---|
| 目标调试 | SWD 连接、当前运行/暂停状态及 PC、复位/暂停/继续、ELF 函数列表、断点及捕获起点 | 上位机通过同一个探针会话控制；区别于离线历史导航 |
| Trace 与采集 | ETM 能力/Trace ID/压缩与周期选项，TPIU 并行端口/路由信息，GPIO、LA 采样率/阈值/深度/通道、开始/停止 | 上位机配置已支持的 CoreSight 能力及 LA；未验收的能力不伪装为可用设置 |
| 固件与时钟 | 用户填写板级 HSE、预期 CPU/TRACECLK；实际 RCC 时钟回读、公式、分频和带宽建议、固件侧初始化职责 | 填写值用于计算和比对；PLL/CPU/供电由目标固件负责，上位机不自动改频 |
| 文件与记录 | ELF/源码、固件指纹、原始记录、解码任务、导入/导出及基准记录 | 上位机文件和离线分析 |

H7B0 当前 PLL1 路径的公式为 VCO=HSE/M×(N+FRACN/8192)，CPU=VCO/P/CDCPRE，HCLK=CPU/AHB 分频，物理 TRACECLK=VCO/R/2。实际时钟源仍以 RCC 识别结果为准，不能把填写的预期主频显示成实测主频。只有支持且已启用的时钟路径才允许进入采集流程。

参考 SWO 页面已有的侧栏 Tab、当前/预期频率区分、计算详情和接线帮助折叠方式。说明文字尽量放在对应 Tab，启动/暂停与采集状态始终可见。

## 函数断点联动流程

载入匹配 ELF → 搜索并选择函数 → 使用空闲 FPB 硬件断点运行至该函数 → 回读实际 PC 与时钟 → 配置 ETM/TPIU 并保持暂停 → 移除本次捕获的一次性起点断点 → LA 进入等待触发状态 → 继续 CPU → 保存波形及完整配置 → 解码。

一次性起点断点在继续前移除，避免重复命中，同时不能先单步执行掉第一条待采指令。长期断点的续跑逻辑需复用调试页的命中处理，保持用户其他断点，不占用或清空不属于本页面的比较器。容量不足、地址不可执行、ELF 不匹配、实际停点不符或超时必须明确报错并清理临时资源。

现有 `target.js` 已具备业务入口临时 FPB 断点。参考主工具 `app/dbg/bp.js` 的编码/能力解析以及 `session.js` 的断点续跑处理，按接口复用所需能力，不直接接入一套会清空现有断点或重复占用探针的完整调试会话。符号可从现有服务端 ELF 解析提供，不必仅为函数列表复制整个前端 DWARF 解析器。

首次使用已完成初始化的业务函数作为采集起点。之前未通过验收的复位入口/启动全过程选项仍不启用；选择函数不代表该函数任意初始化阶段都已通过采集验收。

## 右侧主要工作区域

- 顶部紧凑状态条：当前记录、选中序号/PC、目标状态和质量异常摘要。
- 主区域：可调整比例的执行流/机器码与源码面板，随窗口高度扩展；历史调用栈作为可收起或独立窄面板。
- 调用、火焰图、热点、包和完整性视图通过 Tab 切换；完整性异常始终有入口，但不默认占据大块展示空间。
- 窄屏使用单主面板及切换，不让多个次要面板挤压执行流；保留键盘操作、清晰选中状态和加载反馈。

## 实施顺序与验收

1. 建立基准回归并设计事件索引/分页接口。
2. 实现历史导航、选中位置调用栈和区段可信度。
3. 重做侧栏责任分组及右侧主次布局。
4. 加入符号选择、断点管理与断点起点联动状态机。
5. 离线与浏览器验收后，再在现有 70/35 固件上验证函数断点起点采集、停止、失败清理和配置恢复。

验收重点：1/10 ms 基准结论保持一致；未知状态不变成已证实执行；跨缺口不拼接调用栈；长记录不依赖一次性全量 JSON；函数断点容量与命中/续跑正确；第一条待采指令不会被提前执行；LA 未就绪不启动 CPU；失败不遗留临时断点和探针占用；宽/窄屏主面板可用。

本轮不承诺解决所有 IT 谓词结果、实现完整 GDB 服务端、历史变量、耗时火焰图或无限时长流式采集。这些后续专项的入口仍保留在交接摘要中。
