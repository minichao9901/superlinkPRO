# 独立执行流分析第二版

本轮继续在 `E:\web-etm-trace` 完善，没有接入主工具，也没有改动目标 Flash。
页面仍为 http://127.0.0.1:8766，打开后使用新增的“函数调用 / 火焰图 / 热点 / 完整性”。

## 已实现

- **完整性**：输入与包字节核算、未同步区、未知源、尾部截断、已识别包数、未知条件状态和周期计数元素数量。
- **执行状态**：IT 非分支条件指令在缺少条件结果时标为未知，导出不会将它当作已证实执行；无符号、从 IT 中间开始的情形做保守检测。
- **调用分析**：依据机器码 BL/BLX 及后续地址识别普通调用；返回按已知返回地址闭合，尾跳转和中断进入分开统计。函数切换本身不算调用。
- **火焰图**：聚合调用路径，以路径指令记录数量加权，明确不是耗时图；点击方块放大，支持重置和转到函数执行流。
- **热点**：按函数与源码行统计路径记录数，并单列未知状态数量，点击定位源码。
- **缺口与上下文**：跨缺口不拼接调用栈，采集前祖先保留为未知；异常返回地址改变时不冒认尾调用或同一任务。

## 500 MSa/s 真实样本结果

| 函数 | 路径记录 | 观测普通调用 | 调用占比 | 中断进入 |
|---|---:|---:|---:|---:|
| main | 9068 | 0 | 0% | 0 |
| trace_workload | 1178 | 17 | 10.4% | 0 |
| trace_even | 213 | 71 | 43.3% | 0 |
| trace_odd | 210 | 70 | 42.7% | 0 |
| HAL_IncTick | 66 | 6 | 3.7% | 0 |
| SysTick_Handler | 18 | 0 | 0% | 6 |

普通调用共 164 次。`main` 的 0 表示没有在可信区间观察到调用它的指令，不表示程序没有进入 main。
统计不是调用/秒；初始缺失区不能参与冒充完整窗口的精确调用率。路径指令数含条件分支未成立记录，与执行耗时不同。

当前区间首段调用栈未知；真实父子调用仍可恢复。火焰图以灰色区分未证实的祖先。复杂编译器别名、完整 RTOS 任务归属仍需后续专门适配和验收。

## 变量与局部变量的边界

变量功能目前尚未加入 ETM 页面。

暂停目标后，通过 SWD 读取寄存器与内存，再结合 ELF/DWARF，可以显示全局变量、当前函数参数和可恢复的局部变量。原主工具已有 `app/dbg/locals.js` 与调用栈/CFI 基础，可在独立页面复用。优化掉、不在作用域、位置描述不支持或寄存器无法恢复的变量必须明确显示不可用。

**历史 trace 不能直接提供当时的全部变量值。** H7B0 的 ETM 是 instruction-only。当前值与历史值应为不同面板；不能点击历史 PC 后读取当前 RAM，冒充那一刻的变量。
若需要部分历史变量，可另行记录明确的暂停快照、变量采样或软件事件，并保留实际记录时刻和间隔；这些不等于逐指令的完整变量历史。

依据：[ST H7 trace 能力](https://www.st.com/content/ccc/resource/training/technical/product_training/group0/8a/bf/62/da/24/f0/49/7b/STM32H7-System-Debug_DBG/files/STM32H7-System-Debug_DBG.pdf/_jcr_content/translations/en.STM32H7-System-Debug_DBG.pdf)、[DWARF 位置模型](https://wiki.dwarfstd.org/Clarify_Location_Expressions.md)。
