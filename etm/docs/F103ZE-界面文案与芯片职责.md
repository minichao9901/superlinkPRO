## 二、事实来源（可逐条核对）

| 结论 | 来源 |
|---|---|
| F103 芯片内无 Funnel，ETM 直连 TPIU；PE2～PE6 AF 推挽 50 MHz；并行协议保持 0，不回写 SWO 1/2 | `web/app/target-f103.js:34-46,56` |
| F103 返回栈压缩 / 周期计数被明确拒绝（不是忽略） | `web/app/target-f103.js:28` |
| F103：Trace 输入 = HCLK；4 位 DDR 的引脚 TRACECLK = HCLK ÷ 2 | `web/app/clock.js:3`、`clock.js:60`（`physicalTraceHz = traceHz/2`） |
| F103 上 CPU = HCLK（F1 无 CDCPRE 分频） | `web/app/clock.js:61` |
| H7：VCO = HSE ÷ M × (N + FRACN ÷ 8192)；CPU = VCO ÷ P ÷ CDCPRE；TRACEPORTCK 由 RCC 选 HSI/CSI/HSE/PLL1_R；引脚 TRACECLK = TRACEPORTCK ÷ 2（PLL1 路径 = VCO ÷ R ÷ 2） | `web/app/clock.js:6-7,37-45` |
| 已实板验收型号：`stm32f103ze`、`stm32h7b0`（`traceValidated:true`）；F103 标准/超大容量与 F4、H743 待适配 | `web/app/clock.js:3-7` |
| 连接后 F103 的通路文字、保留位 title、引脚档位文案由 `view.js` 动态覆盖（`view.js:91-97`）；HTML 只负责未连接时的默认说明 | `web/app/view.js:91-97` |
| 采集起点不能选启动入口（Reset_Handler/SystemInit/main 尚未验收） | `web/app/view.js:52` |

## 三、两芯片的操作顺序（界面按 1→2→3→4 一致）

| 步骤 | F103（ETMv3.4） | H7（ETMv4） |
|---|---|---|
| 1 调试 | 载入匹配 ELF → 连接识别（DEV_ID 0x414 + ETMv3）→ 添加断点 → 选采集起点、复位至起点 | 同左，DEV_ID 0x480 |
| 2 时钟 | 填板级 HSE → 读 RCC → 核对 CPU/HCLK 与引脚 TRACECLK（= HCLK÷2） | 同左，另需注意 TRACEPORTCK 与 CPU 是两条独立路径 |
| 3 采集 | ETM/TPIU 配置：引脚固定 50 MHz AF 推挽、并行协议保持 0、两项保留位禁用 | 可选引脚档位；通路为 ETM → Funnel → ETF → TPIU |
| 4 文件 | 保存可重解码记录包 → 解码/导出 | 同左 |

共同点：Web 只配置 Trace 相关寄存器并在停止/恢复时回写；PLL/供电/Flash 延迟由固件负责，网页不改写共享 PLL。

## 五、遗留与待协调

1. **Trace ID 范围（已解决）**：共同合法范围保持 1～111（0x01～0x6F）。`TRACEIDR` 的 7 位掩码只是寄存器字段宽度；0 与 0x70～0x7F 是 CoreSight 保留 ID，不能据此放宽到 127。`EtmTarget.configure()` 已在目标写入之前验证范围。依据：本仓库 `vendor/OpenCSD-1.8.3/decoder/include/opencsd/ocsd_if_types.h` 的 `OCSD_IS_VALID_CS_SRC_ID`，以及 [Arm CoreSight Trace ID 说明](https://developer.arm.com/community/arm-community-blogs/b/tools-software-ides-blog/posts/programming-arm-s-system-trace-macrocell)。
2. **「GPIO 可预配但不能覆盖」的措辞**：我按“业务引脚由固件预配，网页只改 Trace 引脚并在恢复时回写”写入，
   如果原意是别的（例如固件预配的 trace 引脚也不允许网页改），请指出，我按你的说法改文案。
3. 如需在帮助里加 F103 的引脚↔LA 通道对照（PE2～6 ↔ CH0～4，共地、基准滤波 ≤1 点），我可以补一张小表。
