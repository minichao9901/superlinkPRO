# 源码目录 413 修复

2026-10-11。用户选取完整 `stm32h7b0_spi_trace` 源码目录后，“启动 LA 并采集”返回 413 Request Entity Too Large。

## 原因与范围

实际目录有 3,433 个文件，其中旧扩展名过滤规则匹配 2,371 个源码文件，合计 162,218,184 字节（约 155 MiB）。原采集请求将全部文本作为 JSON 一起发送，超过本地服务的 150 MiB 单请求限制。该请求在创建 LA 任务之前已被拒绝，不是 LA 硬件采样限制。

本基准 ELF 的 DWARF 执行行表引用 22 个文件，总计 1,138,244 字节（约 1.09 MiB）。

## 调整

- ELF 信息接口返回引用的源码路径清单。
- 浏览器先匹配文件路径元数据，采用最长相同路径后缀；同分的多个同名文件不擅自选择，会列入歧义提示。只读取匹配的内容，忽略未被此 ELF 引用的 SDK/其他例程文件。
- 源码单独上传，通常按约 4 MiB 分批；单个较大文件单独一批。上传完成形成不可改写的本地源码快照，未完成快照不能用于采集。
- 采集请求仅传 `elfId`、`sourceSnapshot` 及采集/目标参数。服务端复制对应文本到记录的 `sources.json`，导出的记录包仍包含源码，后续离线分析自包含。
- 载入新 ELF 清掉前一份目标的源码快照引用。选择源码后有匹配数、缺失/歧义数及字节数反馈。
- 为历史记录补充源码时，仅在对应 ELF 哈希一致时使用这次匹配结果，支持精确 DWARF 路径键；不会把另一个目标 ELF 的源码自动附加过去。
- 保持原服务容量限制，413 改为可理解的中文提示。

选择目录时浏览器仍会按全目录文件数显示标准“上传”授权框；网页获准后只读取匹配的 22 个文件，并发送给电脑上的本地服务。目标源码现在在目录选择后立即保存快照，采集时不再发送源码内容。

## 验证

- 实际浏览器重新载入基准 ELF，选择完整 3,433 文件目录：`匹配 22 / 22 个文件 · 1.09 MiB · 已保存本地快照`，无浏览器错误。
- 49 项 Python、25 项 JavaScript 测试通过。覆盖文件后缀匹配与歧义、大目录元数据筛选、UTF-8/JSON 批次计数、分批快照合并、未完成拒绝、完成后不可改写、用小请求创建采集记录并保存正确源码、无关源码拒绝及 413 提示。
- 本次没有执行新的硬件采集或操作 SWD。采集请求复制源码快照的行为通过服务端测试验证。

## 用户重新操作

先在原页面断开探针，然后刷新页面加载新版本。重载 ELF，重新选择同一个完整源码目录，确认匹配数与 1.09 MiB 提示，再按原步骤连接、选断点和采集。浏览器的 3,433 文件授权提示仍可能出现，是目录访问提示。
