# ETM 网页初版方案（已确认并实现）

用户已确认实施。当前效果、启动与验收结果见 [网页初版](网页初版.md)。

## 目标与位置

先在 `E:\web-etm-trace` 做可操作的独立初版，使用已烧录的 STM32H7B0 低频固件及真实 Kingst 采集。接口与页面模块按后续接入 `E:\web-serial-rtt-tools` 设计，第一步不改其主页面入口。

## 架构

- 网页：连接现有 CMSIS-DAP 探针，通过 WebUSB 使用 SWD；复用现有探针连接、目标存储器读写、ELF/DWARF 与源码选择模块。
- 本地服务：提供本地页面、KingstVIS Socket API 联动、后台采集任务、文件保存和解码接口。初版使用现有 Python 采集基础。
- 解码：接入 OpenCSD ETMv4 解码器，提供芯片实际 trace 寄存器配置和 ELF 代码镜像；输出包记录、指令范围、异常以及同步/溢出/缺口事件。
- 指令与源码：展开实际执行的 Thumb/Thumb-2 指令范围，将 PC 映射到 ELF 函数及 DWARF 文件/行号。保留执行顺序，明确显示无法恢复的区段。

OpenCSD 是 C++ 原生库，初版由本地服务调用。本地服务与浏览器 SWD 各司其职；之后页面迁入主项目仍可使用同一采集/解码接口。

## 页面功能

| 区域 | 初版功能 |
|---|---|
| 连接与目标 | 探针连接、目标识别、通过 SWD 复位并暂停、继续/暂停 |
| ETM 配置 | H7B0 四位并行 trace 预设，源 ID、配置读取、应用与回读核对；不修改 PLL/系统主频 |
| 采集 | Kingst 连接状态、采样率、采集时长、五通道映射、开始/停止、进度；可选择采集前复位 |
| 记录 | 原始 CSV/KVData、采集参数、trace 寄存器、配套 ELF 哈希；打开旧记录与单独解码 |
| 分析 | 包视图、执行顺序列表（PC/指令/函数/文件/行）、函数与源码位置计数、源码定位、异常/缺口提示 |
| 导出 | 结构化 JSON/CSV、按实际顺序的源码执行流，以及与现有 SWO 页面风格接近的简化源码导出 |
| 实测示例 | 一键加载本次 H7B0 真实 trace、配套 ELF 和测试源码，便于直接查看效果 |

“复位”默认使用 SWD 写目标复位寄存器，不依赖另接 nRESET 线；硬件持续拉住复位不是本初版的默认操作。
当前记录没有逐指令周期时间，页面以执行序号和 PC 为主，不伪造精确时间轴。

## 采集联动与边界

1. 页面保存当前目标配置，按需要复位并等应用初始化，再暂停目标、配置 ETM并回读。
2. 本地服务准备 LA 后台采集；确认 LA 开始后再继续目标，使目标执行落入有效采集窗。
3. 到达指定时长或按停止，保存本次原始数据；停止后可立即解码，也可稍后单独解码。
4. Kingst 的 `start` 命令会阻塞，联动与提前停止需要在真实设备上验证独立控制通路；不以按钮状态代替设备已开始/已停止的证据。
5. 解码前校验源 ID、芯片寄存器、代码镜像与记录配套关系。损坏数据、失同步、overflow、缺口及缺少代码镜像均明确保留，不跨缺口补造路径。

## 实施与验收顺序

1. 先用保存的 500/100 MSa/s 真实记录完成离线包解码和机器码路径恢复，记录任何不支持项或解析错误。
2. 核对固定工作负载中的 `trace_workload`、`trace_even`、`trace_odd`、循环分支和 SysTick 进出路径，与 ELF 反汇编及源码行映射交叉验证。
3. 建本地采集/解码服务，将采集与解码作为独立任务。
4. 实现网页控制和离线记录分析，带入真实示例；确认源码执行流导出保留分支顺序与缺口。
5. 浏览器端验证真实按钮、源码跳转、记录保存/重载与导出，再进行 SWD + LA 联动实测，交付可打开的初版。

解码器选择依据：[OpenCSD 官方项目](https://github.com/Linaro/OpenCSD)，提供 TPIU 解帧、ETMv4 包处理及程序流恢复 API。
