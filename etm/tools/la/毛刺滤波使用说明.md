# KingstVIS 毛刺过滤脚本选项

当前已验证 KingstVIS 3.6.6、MIPI16 的采集档案快照。500 MSa/s 对应 2 ns/采样点；1 点设置对应 2 ns，2 点对应 4 ns。滤波只能处理已采到的短脉冲，不能提高输入带宽、修复漏采的正常边沿或恢复历史数据。数字跳变异常也不能代替示波器对模拟振铃的测量。

## 读取本次采集的实际设置

```powershell
python tools/la/kingst_la.py glitch-filter-info records/<记录ID>/capture.kvdat
```

读取 KVDAT 中的 `glitchFilterSettings` 快照以及二进制头内的真实采样率，显示每个通道是否启用、点数和宽度。指定 `--rate` 时必须与档案一致。直接读取 `vis.config` 得到的是上次写盘的预设，可能落后于运行中的 GUI；不将它作为本次采集配置的证据。

之后的脚本采集/导出默认还会生成 `capture.csv.la.json`；Web 记录的 `session.json` 也保存 `laFilter`，完整性页面显示它。无法取得快照时保留未知状态。

## 生成一个可检查的预设副本

```powershell
python tools/la/kingst_la.py glitch-filter-preset --samples 1 --channels 0 1 2 3 4 --out kingst-filter-1.config
```

这一步不修改运行中的 KingstVIS。副本默认选择“下次启动保留”，只替换两个过滤相关字段，保留其它配置原始字节，包括原文件中的本地编码。

## 应用到下次启动

先正常退出 KingstVIS，然后执行：

```powershell
python tools/la/kingst_la.py glitch-filter-preset --samples 1 --channels 0 1 2 3 4 --apply
```

脚本备份原配置后更新预设；再启动 KingstVIS 后应在过滤窗口回读，并用下一次 KVDAT 快照确认。此路径已通过临时文件的读写、备份及运行中拒绝覆盖测试，**本轮未重启软件验证预设加载**，不将写文件成功当作原生设置已生效。

关闭选定通道的过滤使用 `--disable`；配置 2 点使用 `--samples 2`。未选通道保持原值。已有输出副本拒绝覆盖。

## 为什么不在 capture 中直接增加原生实时开关

公开的 [KingstVIS Socket API 说明（厂商文档镜像，2026-04-11）](https://raw.githubusercontent.com/andy-qingcai/KintstvisMcp/main/docs/socket_api_text.txt) 只有部分控制功能，没有公开毛刺过滤命令。本机尝试 `get-glitch-filter` / `get-glitch-filter-settings` 都返回 `invalid command`。这证明这两个名称不可用，不能证明未来版本不会提供接口。

因此本版提供的是**启动预设**与**采集快照读取**，不宣称通过 Socket 实时改变过滤值，也不在后台强制退出/重启软件。

启用 GUI 滤波后，本轮 KVDAT 与 CSV 的边沿逐一相同。保存 KVDAT 便于复查，但不能据此声称保留了滤波前的数据。本轮没有同一次采集的未滤波副本，不能量化滤波前后改善，也不能假设离线关闭滤波能找回被去掉的边沿。短脉冲过滤的边界及连续脉冲合并行为尚未独立验收，不实现一个冒充 Kingst 原生算法的后处理滤波器。
