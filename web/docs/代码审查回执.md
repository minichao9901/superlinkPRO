## 三、数据/设计疑点：2/2 处理

**9. `flash_length` 偏小** —— 判断：**是真问题**，而且踩中过一次的东西（`_checkRange` 会把合法固件拒掉，
还提示"芯片选对了吗？"）。改法：

- `algos.js` 新增 `SERIES_MAX_KB`（各系列**最大**成员）+ 纯函数 `checkFlashRange()` + `F1_DEV`（DEV_ID → 页粒度 + 容量档）；
- 硬上限用**系列最大值**（F1 有 DEV_ID 时用密度档），越过算法自带的 `flash_length` 只**提示**一次
  （"算法自带区间常按系列最小成员填，小容量型号会在编程时报错"）；
- 没去读各系列的 flash 容量寄存器（F1 的 `0x1FFFF7E0` 那类）—— 地址我没法在没板子的情况下逐系列核实，
  写错会**再次**拒掉合法固件。留作后续（有板子时按 DEV_ID 的先例补）。
- 对账脚本 `tools/dev/check-flash-plan.mjs` 新增一节：每个系列"打满上限收 / 超一点拒 / 低于起址拒"，
  外加 F1 的 DEV_ID 判定（0x410 中容量 256KB 固件必须拒、0x414 大容量 512KB 必须收）。

**10. 「绝对时间」复选框是摆设** —— 判断：**控件在就把语义做实**（而不是删）。现在
未勾选 = **自页面打开起的相对时间** `[+00:12.345]`，勾上 = 当天钟点 `[14:03:22.123]`。
`ui.selftest.mjs` 的"时间戳开关"步骤两种都验（顺便修好了它原来只认钟点格式的断言）。

## 六、与审查意见的分歧（就一条）

第 7 条给的建议 `if (!this.running && this._awaitDef) break;` 我没有照抄：DEF 到达后 `_awaitDef` 立刻变 false，
而 START 的 STATUS 轮询还要跑 120~240 ms，这段窗口里条件成立、新数据**照样被丢**。
改用独立的 `_capturing` 开关（start 打开 / stop 关掉），语义是"这一轮采集还开着吗"，
与"running（探针侧已确认在采）"解耦。第 13 节测试把两个方向都钉住了。
