# SPI/QSPI 桥 · 通用「寄存器」面板与定时采集（设计说明）

`#spi` 页新增两块：

1. **「寄存器」面板** —— 按"器件档位"读一段寄存器回来（默认 128 B = 16×8 表），
   每个字节能点开 8 个 bit 单独改，改完「只写改动 / 整块写回」。交互与 `#i2c` 的寄存器面板**完全一致**
   （同一份 `app/ui/reg-grid.js`）。
2. **定时采集** —— 脚本区支持 `loop <周期> … end` / `every` / 行尾 `as 名字=表达式`，
   配套「实时值」tab（变量表 + 迷你曲线）。SPI 接口的 ADC / 传感器就是"按周期读一次、把字节换算成物理量"。

I2C 侧做同样的事容易得多：寄存器访问只有**一种**形状（`START dev+W + 子地址 + [rSTART dev+R + 读] + STOP`）。
SPI **没有地址总线**，寄存器号怎么发、读命令长什么样、要不要 dummy、一帧能读多少、多字节读会不会自动递增，
**全是各器件自己定的** —— 所以这一页的第一件事不是画表格，而是把"常见器件的约定"总结成一张档位表。

---

## 1. 常见 SPI 器件的寄存器访问约定（档位表的事实来源）

> **核实口径**：下表每一条都来自**手册原文**（PDF 全文检索）或 **Linux mainline 驱动源码**；
> 标 ❌ 的表示**没取到原文**（站点 403/404、无存档），本面板**不把它当结论用**。
> 逐条出处（含页码/章节）见 §1.4 的来源清单。

### 1.1 寄存器型（有寄存器号）

| 器件 | 读的线上形状 | 写的线上形状 | 地址宽度 | dummy | 多字节读自增 | 模式 / 上限 | 核实 |
|---|---|---|---|---|---|---|---|
| **MPU-9250 / MPU-6000** | `0x80 \| reg`（bit7=R/W，A6:A0） | `reg & 0x7F` | 并入 opcode（7 位） | **0** | 有（burst） | Mode 0；**全寄存器 1 MHz / 传感器+中断寄存器 20 MHz** | ✅ 手册 |
| **LSM6DS3TR-C** | `0x80 \| reg`（SDO 第 8 拍才驱动） | `reg & 0x7F` | 并入 opcode（7 位） | 0 | **由 CTRL3_C(12h).IF_INC 控制**（默认 1） | 10 MHz | ✅ 手册 |
| **ADXL345** | 单字节 `0x80 \| reg`；**多字节必须 `0xC0 \| reg`（MB=bit6）** | `reg & 0x3F` | 并入 opcode（**6 位**） | **0** | 有，但**必须显式置 MB** | **Mode 3**（CPOL=1/CPHA=1）；5 MHz | ✅ 手册 |
| **BMP280 / BME280** | `0x80 \| reg`，**控制字节后数据立刻出来** | `reg & 0x7F`，**写不自增**（控制字节+数据成对） | 并入 opcode（7 位） | **0**（见下面的"重大纠正"） | 读：有；写：**无** | Mode 00/11（CSB 下降沿后 SCK 电平自动选）；10 MHz | ✅ 手册 |
| **MCP23S17** | opcode `0x41`（`0100 A2A1A0 1`）+ **独立寄存器地址字节** | opcode `0x40` + 地址字节 | **独立 1 字节** | 0 | 有（顺序模式：不抬 CS 即下一地址） | Mode 0,0 / 1,1；10 MHz | ✅ 手册 |
| **nRF24L01+** | `0x00 \| reg`（5 位地址） | `0x20 \| reg`（仅 Power Down/Standby 有效） | 并入 opcode（**5 位**） | 0 | 有，且多字节寄存器是 **LSByte 先** | 10 MHz | ✅ 手册 |
| **ICM-20602 / ICM-20689** | 与 MPU 同族（`0x80\|reg`） | `reg & 0x7F` | 并入 opcode（7 位） | 0 | 有 | Mode 0 | ⚠️ **驱动旁证**（TDK 手册 403，按 Linux `inv-mpu6050` 同框架推断） |
| **ADS1256**（24 位 ΔΣ） | 命令**两字节打包**：`0001 rrrr`(0x10\|reg) + `0000 nnnn`(n=个数−1)，命令后要等 **t6=50τCLKIN** | `0101 rrrr`(0x50\|reg) + nnnn + 数据 | 并入 opcode，**第二个字节是数量** | 隐式延时（不是 dummy 字节） | 有，**越界回绕到 0 号** | fSCLK ≤ fCLKIN/4 | ✅ 手册 |
| **ADS8688** | **16 位命令字**：bit15:9=地址、**bit8=0 读**；数据从第 16 个下降沿起 | 同左但 **bit8=1 写**，随后 8 拍回显 | 并入 16 位命令 | 读需 16 拍哑相位 | **无** | 17 MHz；CS 跨整帧 | ✅ 手册 |
| **MCP4131**（数字电位器） | 16 位命令：`AD3:0 \| C1C0(=11) \| 数据`；SDO 第 7 位是 **CMDERR** | `C1C0=00` 写（16 位）；`01/10` 递增/递减（8 位） | 并入命令 | 0 | **无** | 10 MHz（SDI/SDO 复用时读仅 250 kHz） | ✅ 手册 |
| **W25Q32JV**（NOR） | `03h`+24 位地址（无 dummy）／`0Bh`+地址+**8 dummy 时钟**／`05h`、`9Fh` 无地址 | `02h`+24 位地址+数据（页内自增、跨页回卷），写前 `06h` WREN | 独立 3 字节 | 0 或 8 拍 | 读：有 | Mode 0/3；03h 50 MHz、Fast/Quad 104~133 MHz | ✅ 手册（Rev A1） |

### 1.2 命令型（没有寄存器号，一次转换 = 一条命令）

| 器件 | 线上命令 | 回读 | 结果怎么解 | 核实 |
|---|---|---|---|---|
| **MCP3008**（10 位 8 通道） | 起始位(1) + SGL/DIFF + D2D1D0，**起始位前允许前导 0**；D0 后再 1 拍采样保持 | 3 B（24 拍） | **null 位不是数据**：`u16be(1) & 0x3FF` | ✅ 手册 |
| **MCP3208**（12 位 8 通道） | 同上形状 | 3 B | `u16be(1) & 0xFFF` | ✅ 手册 |
| **MAX6675**（热电偶，只读） | **不发命令**（空 tx） | 2 B / 16 拍 | D15 是哑符号位 → `u16be(0)>>3*0.25` ℃（D2 = 断线） | ✅ 手册 |
| **MAX31855**（热电偶，只读） | **不发命令** | 4 B / 32 拍 | `i16be(0)>>2*0.25` ℃（D31 符号、D16 故障标志、D15:4 冷端） | ✅ 手册 |
| **SSD1306**（OLED） | 4 线：**D/C# 引脚**区分命令/数据（**没有 0x00/0x40 控制字节**，那是 I²C 的） | 串行只允许写 | —— | ✅ 手册 |
| **GC9A01 / ST779x**（TFT） | 4 线：D/CX 引脚；3 线：**帧第 1 位**即 D/CX | MIPI DCS 命令 + N 参数 | 命令表驱动（屏页在做） | ✅（GC9A01）；❌ ST77916 未取到原文 |

### 1.3 从这张表提炼出的**必填字段**（本面板的实现依据）

| 字段 | 为什么必须有 |
|---|---|
| `readOp` / `writeOp` | 读位放 bit7 还是别处、写得先清哪一位（nRF24 的方向位在 bit6；ADS8688 在 bit8） |
| `addrMode` = 并入 opcode / 独立字节 / 无地址 | `0x80\|reg` 与 MCP23S17 的"opcode + 地址字节"是两种完全不同的时序 |
| `addrBits`（并入时） | MPU/BMP 是 7 位、ADXL345 是 6 位（bit6 是 MB）、nRF24 是 5 位 |
| `addrBytes`（独立时） | MCP23S17 = 1 B；NOR 那种是 3 B |
| `dummy` | **多数器件是 0**；W25Q 的 `0Bh` 是 8 拍；ADS8688 读要 16 拍哑相位。给错 = 数据整体错位 |
| `dataBytes`（每寄存器几字节） | 16/24 位寄存器要按宽度分组显示与对齐写回 |
| `autoInc` / **`autoIncWrite`** | **读自增与写自增是两件事**（BMP280 读自增、写不自增）；不自增时只能一寄存器一帧 |
| **`multiReadBit`** | ADXL345 的 MB（bit6）—— 少置它 burst 读会"每 8 拍停在同一个寄存器"（6 轴三次一样） |
| `lines` | 标准 SPI 是 1 线；双/四线只有 NOR 那类用 |

### 1.4 三条把常见写法纠正过来的事实（**别按网上的老偏方改回去**）

1. **BMP280 读不需要 dummy 字节。** 手册 §5.3.2 Figure 11（*SPI multiple byte read*）里控制字节之后
   数据立刻出来。需要 dummy 的是 **BMP380/BMP580** —— Linux `drivers/iio/pressure/bmp280-spi.c` 里
   `bmp380_regmap_spi_read()` 的注释写着 "the first byte needs to be dropped"，而
   `bmp280-core.c` 里只有 `bmp380_chip_info` / `bmp580` 把 `.spi_read_extra_byte = true`，
   **bmp280/bme280 都是 false**。BMP180 才要 dummy —— 这个习惯被抄到了 BMP280 上。
   **BMP280 真正的坑是"写不自增"**（手册 Figure 10 标题就写着 *not auto-incremented*）。
2. **ADXL345 也不要 dummy**，但**多字节读必须置 MB 位**，而且它是 **Mode 3**（CPOL=1/CPHA=1）。
   手册原文："(MB …) **must be set**. After the register addressing and the first byte of data, each
   subsequent set of clock pulses causes the ADXL345 to point to the **next register**"；
   Linux `adxl34x-spi.c` 把三个 opcode 写死为 `reg&0x3F` / `0x80|reg` / `0xC0|reg`。
3. **ADS1256 / ADS8688 / MCP4131 这类"命令自己打包地址/方向/数量"的器件，
   无法用"opcode + 地址 + 长度"两三个字段描述** —— 面板**不内置**它们（ADS1256 的关键是不存在的档位），
   要调就用「命令表」或脚本按手册手写（ADS1256 还得在命令与数据之间插 `delay`，t6 = 50 τCLKIN）。

## 2. 面板怎么用（三步）

1. **选档位**：`器件档位` 下拉把上表的默认值填进字段（下拉的 hover 里有"把握程度 + 出处"）；
   每个字段仍可改（**档位只是默认值**）。假探针切到「寄存器器件」时选 BMP280 就对得上。
2. **读取**：`起始寄存器 + 个数`（默认 128）。自增器件 = **一条命令连读**；不自增 = 一寄存器一帧；
   多字节读按需自动置 `multiReadBit`（ADXL345 的 MB）；超过单帧读上限（480 B，见 §4）自动分帧。
3. **改 → 写回**：点任意字节 → 8 个 bit 的开关板（点一下翻转；也能直接敲十六进制）。
   `只写改动` 会把改过的下标合并成帧（相邻的合并、断开的分开），**写不自增的器件自动"一寄存器一帧"**
   （16 位寄存器还会把改动补齐成整寄存器）；`整块写回` 则整段下发。
   **写回成功后才更新"器件现值"**，黄框随之清掉。

两个安全阀（与 I2C 面板同款）：

- **档位/起始/个数在读取之后被改过 → 拒绝写回**（否则会把旧配置读回来的数据按新配置写下去）。
- 每帧都带 RSP：**status 非 OK 就不更新"器件现值"**，表里保留你的改动（不会"看着写成功了其实是盲写"）。

## 3. 定时采集（`loop` / `every` / `as`）

```text
xfer cmd=0x80|0x75 rx=1 as who=u8(0)          # 一次性：先认片子
loop 20ms
  xfer cmd=0x80|0x3B rx=6 as ax=i16be(0)/16384, ay=i16be(2)/16384, az=i16be(4)/16384
end
```

- 语法与 `#i2c` 的脚本区**同一套**（`loop 周期 [轮数] … end`、`every 周期 [轮数]`、`once`、
  行尾 `as …` / `every …`），学一次两边都会用。
- **`cmd=` 支持位运算表达式**：`0x80|0x3B`、`0x40|(0x2<<1)` —— 寄存器面板那套 opcode 可以直接写进脚本。
- 偏移是**这一帧自己的读数据**上的偏移（SPI 一次 xfer 通常就是一个寄存器 / 一次转换）。
  这是与 I2C 侧唯一的语义差别：那边是"一次逻辑读"（多帧拼成一块），这边是"一帧一块"。
- 表达式限制：**一个取字节函数 + 常量运算**（`u16be(1)&0x3FF` 可以，两个取字节函数拼起来不行）——
  与 I2C 侧同一个解析器，见那边的语法速查。
- 「实时值」tab：变量 / 最新 / 最小 / 最大 / 次数 / 实测频率 + 迷你曲线；实测频率按**首末两次采样之间**算
  （不按"到现在为止"，否则跑停之后数字会一直掉）。
- **采集只晚不丢**（与 `#i2c` 的 runner 同口径）：周期比"一次发送"还短时这一拍会迟（如实记 `迟 N` 与日志），
  但**采样点不会少**；`loop … 3` 的轮数按**成功采样**算，一次失败的发送不吃掉用户要的那一轮。

## 4. 帧上限与"整包"陷阱（两条硬约束）

| 约束 | 值 | 为什么 |
|---|---|---|
| 单帧 `tx` | 492 B | 帧头 12 B + 512 B 包 |
| **单帧 `rx`** | **480 B**（面板取的保守值） | RSP 是 `8 B 头 + 数据`；数据取到 504 会正好填满一个 512 的 bulk 包，主机"收满或收到短包"永远等不到短包（I2C 侧同一个坑，那里是 503 封顶） |

读计划会按 480 B 自动分帧；多读就多几帧（每帧重发命令 + 新的起始地址，对自增器件是正确的）。

## 5. 自测与判据

| 入口 | 咬什么 |
|---|---|
| `make test-spi-regs`（纯 Node，**97 项**） | 档位 → 帧构造（并入/独立/无地址、dummy、**写自增与读自增分开**、**ADXL345 的 MB 位**、16 位寄存器、单帧上限分帧）；命令型 ADC 的命令字节与收发等长；**端到端**（假器件：读 128 → 改 → 只写改动 → 回读逐字节对账）；**dummy 给错 → 数据整体错位**；**读/写不自增的两个现场症状**（连读原地踏步、一帧多字节只最后一个生效）；定时采集（拍数、变量、轮数自停、停止即停）；DSL 语法（loop/every/once/行尾 as/位运算 `cmd=`）；**档位表里不该有的器件确实没有**（ADS1256）+ 把握程度标注 |
| `make test-spi-page` 的桥页套件（真页面 + 假探针） | §10b：切 tab、128 寄存器画成 16×8、首末字节与假器件对账、点字节改 bit、只写改动落到假器件、dummy 给错的报错路径；§10c：切到 ADC、跑 loop 采集、拍数与变量、值在动、停止即停、胶囊状态 |

假器件（`app/spi/mock.js`）：

- `SpiRegDevice` —— 可配成 BMP280 风格（dummy 1）或 MPU 风格（dummy 0）、`autoInc` 可关；
  **会如实复现两个真机症状**：dummy 少给 → 输出整体错位；不自增 → 连读全是同一个寄存器。
- `SpiCmdAdc` —— MCP3008 风格，采样值是活的正弦（每通道一个相位），命令缺起始位 / 差分模式会明确拒绝。
- ⚠️ SPI 总线上没有器件地址，所以**同一时刻只挂一个末级器件**：侧栏「假器件」下拉在
  `回环 + NOR` / `寄存器器件` / `命令型 ADC` 之间切换。切到 ADC 之后，"回环自检"不再代表跳线
  （那颗末级已经不是跳线了）。

## 6. 踩过的坑（别改回去）

1. **写帧也必须带 RSP**。第一版按"只有读要应答"写，结果写回是**盲写**：器件没 ACK、片选接错都看不出来，
   表面还显示成功。现在每帧都带 RSP，`status` 非 OK 就不更新"器件现值"。
2. **命令型器件是全双工**：`tx` 与 `rx` 等长（MCP3008 是 3+3）。假探针第一版把"等长收发"一律当**回环**，
   于是命令型 ADC 的帧永远路由不到器件模型（回环自检那条路依赖等长形状）。现在器件可以用
   `fullDuplex = true` 声明"我也认全双工帧"，回环只在末级是跳线（NOR 模式）时才接管。
3. **`tokenize` 不能放在 try 之外**：解析器为了嗅行首关键字先 tokenize 了一次，而 `tokenize` 对没配对的引号会抛 ——
   结果是 `xfer cmd="0x03` 这种行**直接抛穿整个解析**，而本该作为"第 N 行报错"收集起来。嗅探改用正则。
4. **`as` 的值会被空格切开**：`as ax=i16be(0)/16384, az=…` 直接丢给 `key=value` 解析器会被当成"不认识的 key"。
   行尾修饰（`as` / `every` / `tag`）要在建帧参数之前**摘走**。
5. **DSL 的 `cmd=` 要支持位运算**：`0x80|0x3B` 是这一页最自然的写法，不支持就只能人脑先算成 `0xBB`（实测很容易算错）。
6. **16 进制格式化别叠加前缀**（与 I2C 面板同一个坑）：`hex2()` 自带 `0x`，多字节 join 会得到 `0x010x3C`。
7. **`#spi` 的 `.dockpage` 一旦新增 tab，页面自测里"tab 列表"那条断言必须同步改**（否则它红得很有道理）。
