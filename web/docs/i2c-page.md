# 「USB→I2C」页（`#i2c`）—— 设计说明

> 页面：`index.html` 的「USB→I2C」标签（排在「SPI/QSPI 屏」之后）· 代码 `app/i2c/`
> 协议真源（固件侧）：`akaLinkPro/firmware/application_5301/src/i2c_bridge/i2c_bridge_proto.h`
> 网页侧交接文档：`akaLinkPro/docs/web-handoff-i2c-bridge.md`
> 固件分支：`feature/usb-i2c-bridge`（**仅 HPM5301EVKLite**；akaLinkPro 原板编成空实现，HID 0x36 回"不支持"）
> 自测：`make test-i2c` · `make test-i2c-dsl` · `make test-i2c-page` · `make i2c-hw`

把探针当「USB 转 I2C 主机」用：网页选器件 / 填子地址 / 收发字节，探针在目标总线上产生
`START … repeated START … STOP`。定位和 SPI 桥一样是**工具**，不是高速数据面。

---

## 1. 和 SPI 桥的三处不同（都是 I2C 的物理特性决定的）

| | SPI/QSPI 桥（0x35） | I2C 桥（0x36） |
| --- | --- | --- |
| 数据面 | 另开一对 bulk（0x0B/0x8B）+ 有序帧流 | **只走 HID**：一条报文装一次事务（写 ≤51 B / 读 ≤54 B） |
| 传输引擎 | 轮询 / DMA 两路可配 | **纯轮询**（100 kHz 下一字节 90 µs，DMA 的固定开销比它还大） |
| 执行位置 | 帧在主循环按预算执行 | 事务在主循环执行；HID 中断只**登记请求**（一笔最长 ~5 ms，绝不占着 USB 中断） |
| 主机侧取结果 | 发帧 → 等应答帧 | 发 XFER → **轮询 RESULT** 到 `PENDING` 清零 |

所以本页**没有**「连接数据端点」这一步 —— 连上 HID 就能干活。

## 2. 接线（HPM5301EVKLite 的 J3 排针）

| 信号 | 探针 | J3 脚 | 说明 |
| --- | --- | --- | --- |
| SDA | **PA28** | **J3[21]** | 板丝印还是 SPI1 时代的 `SPI_MISO`；**板上没有上拉** |
| SCL | **PA29** | **J3[19]** | 板丝印 `SPI_MOSI`；有 R6 10k 上拉，**与 USB0_OC 网络共用**（USB 限流报故障时会把 SCL 拉低 → 发 RESET 恢复） |
| GND | — | J3[6]/[9]/[14]/[20]/[25]/[30]/[34]/[39] | 必须接 |
| 3.3V | — | J3[1] / J3[17] | 给从器件供电（器件另有电源可不接） |

- 硬件外设是 **I2C3**，与 SPI2(PB10~PB15)、SWD(PA04~PA08)、CDC UART2(PB08/PB09)、UART0(PA00/PA01) 都不冲突。
- **上拉**：SCL 有 R6 10k，SDA 没有。常见 I2C 模块自带 4.7k~10k，接上就够；
  裸芯片要么外接电阻，要么打开内部上拉应急（`SET_CFG` 的 `pullup=1`，电流弱、只适合低速短线）。
- ⚠️ **桥使能期间，SPI 桥的辅助脚 pad16/17（就是 PA28/PA29）会被拒**（固件里 `i2c_bridge_owns_pad()` 交叉检查）。
  要用那两根当 SPI 辅助脚，先把 I2C 桥**失能**。
- ⚠️ 探针复位 / 重新烧录后，桥回到**未使能**、配置回默认（100 kHz、上拉关）——
  所以页面每次连接后都会 `GET_CFG` 并自动补一次 `ENABLE 1`。

## 3. 报文口径（🚨 这里最容易错一个字节）

固件 proto.h 按**含 Report ID 的 64 B** 编号；网页侧 `AkaLinkHid.xfer()` 已经把 Report ID 剥掉
（WebHID 把它放在 `event.reportId`，不在 `event.data` 里），所以**本页一律用网页口径**，两者差 1：

```
请求  data = [action, ...参数]      → 线上 payload = [长度, 0x36, action, ...参数]
响应  res[0]=长度  res[1]=0x36  res[2]=action 回显  res[3..6]=状态字(u32 小端)  res[7..]=数据
```

| 内容 | 网页口径 | proto.h（含 Report ID） |
| --- | --- | --- |
| 状态字 | `res[3..6]` | `res[4..7]` |
| STATUS 的 10 个 u32 | `res[7..46]` | `res[8..47]` |
| GET_CFG 的 16 B | `res[7..22]` | `res[8..23]` |
| RESULT：err / n / data | `res[7]` / `res[8]` / `res[9..]` | `res[8]` / `res[9]` / `res[10..]` |
| XFER 参数起点 | `data[1]` | `req[4]` |

**三重印证**（改协议层前请重新核这三处）：proto.h（+1）、web-handoff 文档（网页口径）、
已上板验证的 `script_test/i2c_bridge_test.py`（`Resp` 类用的就是 `r[3:7]` 与 `r[7:]`）。
`tools/selftest/i2c-proto.test.mjs` 第 1 节把这些逐字段钉死了。

### XFER 的四种线序（都由固件一支笔完成）

| 组合 | 线上 |
| --- | --- |
| `wr=0, rd=0` | `START + dev+W + STOP`（地址探测，只问 ACK/NACK） |
| `wr>0, rd=0` | `START + dev+W + 子地址 + 写数据 + STOP` |
| `wr=0, rd>0, addr_len=0` | `START + dev+R + 读 + STOP`（纯读） |
| 其余 | `START + dev+W + 子地址+写数据 + **repeated START** + dev+R + 读 + STOP` |

⚠️ **子地址是一串字节，不是 u32** —— `addr[0]` 先发。早期固件按"u32 小端取低 addr_len 字节"解释，
`addr_len=1` 时发出去的恒是 `0x00`，读 EEPROM 永远从地址 0 开始。主机侧也别再犯：
本页 `rd 0x50 0x0010 2` 会在线上发 `00 10`（按**写出来的十六进制位数**铺字节）。

## 4. 命令协议（本页自己定的）

脚本区与命令表**走同一套解析器**（命令表先被转成脚本文本再解析），所以两处行为完全一致。

```
# 注释（# 或 //）到行尾；空行忽略

scan                                 扫 0x08..0x77，出 ACK 地址列表（14 B 位图）
ping 0x50                            地址探测（只问 ACK）
rd  <dev> <子地址> <读长>             写子地址 + repeated START 读
rd  0x50 0x00 256                    读长随便写（≤4096）—— **超过 54 B 自动分片**，日志只出一行
rd  0x50 0x00 256 ptr                同上，但走「地址指针自增」连续读（FIFO 型器件必须用它）
rd  0x50 - 8                         子地址写 `-` = 不带子地址的纯读
wr  <dev> <子地址> <b0> <b1> …        写子地址 + 数据（单次 ≤51 B，**写不自动分片**）
wr  <dev> <子地址>                    只发子地址、不带数据 = **把地址指针推到 N**
wr  0x50 - 11 22                     不带子地址的纯写
xfer dev=0x50 addr=0x00,0x10 wr=11,22 rd=0     字段名写法（与线上字段同名）
delay 10ms                           延时（裸数字 = µs；吃 us/µs/ms/s）

# 定时读 / 定时写（这就是 while(1)）
loop 100ms                           块开始：里面每一行都按 100ms 周期跑
  rd 0x68 0x3B 14
end
loop 500ms 20 … end                  带次数：跑 20 轮自己停（省略 = 一直跑到点「停止」）
every 100ms                          不成块也行：把**后面所有行**设成 100ms 周期
every 100ms 50 / once                周期 + 次数 / 取消周期
rd 0x68 0x75 1 every 500ms           行尾覆盖：这一行单独定时

# 解码（读回的字节 → 有名字的数，见 §5）
rd 0x68 0x3B 14 as ax=i16be(0)/16384, az=i16be(4)/16384

# C 表行（列序 = 线上 XFER 字段，可从固件源码直接贴）
{dev, addr_len, addr, wr_len, rd_len, data},
{0x50, 1, 0x0000, 0, 8, NULL},
{0x50, 1, 0x0010, 4, 0, (uint8_t[]){0x11, 0x22, 0x33, 0x44}},
{0x00, 0, 0, 3, 0, "ABC"},           字符串字面量也吃
{0x68, 1, 0x3B, 0, 14, NULL}, as ax=i16be(0)/16384 every 50ms
```

**进制**：设备地址与子地址**默认十六进制**（I2C 惯例，`50` 就是 `0x50`）；读长 / 延时 / 周期是十进制。
**上限**：单次写 ≤51 B（写不自动分片）、一次逻辑读 ≤4096 B（>54 B 自动分片）、子地址 ≤4 B、
器件地址 7 位 —— 全部在解析期带行号拦住。

### 长读自动分片（实现细节不该让人自己拆）

一次 HID 报文只能装 54 B 读数据（响应侧只剩 56 B），这是**报文的限制**，不是 I2C 的限制。
所以 `rd 0x50 0x00 256` 是**一条逻辑读**：`session.readLong()` 内部按 `planRead()` 拆成 5 笔、
拼回一整块再交给上层，**中间那 5 笔不往日志里写**，只出一行：

```
读 0x50[00] × 256 → 256 B · 分 5 笔 · 62.3 ms  00 01 02 03 …
```

- 默认 `chunk='reset'`（**每片重发子地址**）：EEPROM、寄存器型器件（MPU6050 / ADS1115 / Si5351）全都成立，最稳。
- `ptr`（`chain` / `chunk=ptr` 也行）：地址指针自增 —— 先发一次零长度写把指针推过去，
  之后每片不带子地址。**读一次弹一个数的 FIFO 型器件必须用它**，否则每片重发子地址会把数据丢光。
- 失败时**不返回半截数据**，但会明确说清断在哪一片、已经读回多少：
  `读 0x30[00] × 200 → 第 3/4 片（片@+108）失败：地址相位没 ACK（已读回 108 B，这部分丢弃）`
- `as` 解码作用在**拼起来的整块**上（`rd 0x50 0x00 256 as b255=u8(255)` 里的偏移 255 有效）。

⚠️ **写不自动分片**：EEPROM 页写跨页会**绕回本页页首**（后面的字节盖上前面的），
自动拆是危险的 —— 要写大块请自己按页 / 按寄存器块拆。

⚠️ **导出 C 表时长读会被展开成多行**：C 表的 `rd_len` 是**线上字段**（一个字节，最大 54），
塞不下 256。展开后的字节流与页面上实际发出的逐笔一致，但 `as` 表达式没法逐行表达 ——
要**无损往返请用「导出 JSON」**（它带 `chunk` 与 `as`）。

### 任务边界（🚨 这是本页最容易做错、也最难在真机上发现的地方）

`loop … end` / `every` 划出的不只是"周期"，还是**不可拆的执行单元**（`runner.js` 的 `buildTasks`）：

```
loop 200ms
  wr 0x48 0x01 C3 83     ← 启动一次单次转换
  delay 10ms             ← 等转换（128 SPS ≈ 7.8 ms）
  rd 0x48 0x00 2         ← 取结果
end
```

这三条必须**整段按顺序跑**。如果做成"每行各自按 200 ms 定时"，读到的会是上一次
甚至上上次的转换结果 —— 值看着"像在动"，其实全错。MPU6050 的"一次读 14 B"、EEPROM 的
"页写 → 等 tWR → 回读"同理。`tools/selftest/i2c-dsl.test.mjs` 第 5 节把这个结构钉死了。

## 5. `as` 解码表达式

读回来原样是一串十六进制；`as` 把它变成有名字、有量纲的数（页面右下「实时值」面板显示 + 画曲线）。

```
as ax=i16be(0)/16384, ay=i16be(2)/16384, az=i16be(4)/16384
as tC=i16be(6)/340+36.53
as v=i16be(0)*0.000125
as cfg=u16be(0), mux=u16be(0)>>12&7
```

- 函数（括号里是**字节偏移**，省略 = 0）：`u8 i8 u16be i16be u16le i16le u24be u32be i32be u32le f32be f32le`
  —— 多字节默认**大端**（I2C 器件的寄存器几乎都是大端：MPU6050 / ADS1115 都是）。
- 运算：`+ - * / % >> << & |`，**严格从左到右，没有优先级**（`raw/340+36.53` = `(raw/340)+36.53`，
  正是"先换算再偏置"的自然写法）。要别的顺序就拆成两个变量。
- 读不到的偏移会给告警（不会静默给 0）。

## 6. 页面结构

```
左栏：探针·I2C 桥（连接/重连/假探针）· 桥配置（SCL 档/上拉/重试）· 使能与状态（计数器/状态字）
      · 接线与排障（PINTEST / DBG）
右列：┌ tab 栏：[扫描总线][命令表][寄存器][脚本][实时值]   ▶运行中·98拍·失败0   [停止] ┐
      │ 当前 tab 的内容（吃满整块高度）                                        │
      ├──── 拖动条（调整日志高度，存 i2c.logH）───┤
      │ 日志（常驻）                                                           │
      └ 统计条 ┘
```

**为什么是 tab**：原来五张卡片纵向堆在一个滚动区里、每张都被迫限高（命令表只能看见 7 行、
脚本框一屏就满），而且"正在跑的结果"与"实时值"永远没法同屏。tab 化之后每块吃满高度。

**为什么日志和运行胶囊仍然常驻**（这条别改）：
- 日志是 tab 化之后**唯一的过程视图**（"发生了什么"），藏进某个 tab 就没人看得到了；
- tab 栏右侧那个**运行胶囊**（`▶ 运行中 · N 拍 · 采样 M · 失败 K`）是跨 tab 传达"还在跑"的
  唯一地方 —— 少了它，切到「脚本」改一行就忘了命令表还在 while(1)。旁边就是共享的「停止」。

| tab | 内容 |
| --- | --- |
| **扫描总线** | 扫描按钮 + 摘要 + 结果表（器件 / 可能型号 / 选用·读 1 字节）+ 选中器件框 |
| **命令表** | 工具行 + 24 行表 + 提示。一行一次事务；器件格留空 = 跳过该行；操作 = 读 / 写 / 探测 / 延时（格子按操作自动灰掉）；读长格可以写 `256` 或 `256 ptr` |
| **寄存器** | 工具行（器件 / 起始 / 长度 / 地址宽度 / 读法 / 写分片 / 片间等待 + 读取·只写改动·整块写回·丢弃改动）+ **16×8 字节表**（地址列 + 16 个字节格 + ASCII 列）+ 摘要。点任意字节 → `.bitpop` 位开关板（8 个大方块，与原值不同的位套黄框，也能直接敲十六进制）。**读回来的值 = 「器件现值」**，只有点写回才发 I2C —— 见 §6.1 |
| **脚本** | 工具行 + 文本框（可拖高）+ 摘要/导出行 + 错误表 + 语法速查（折叠） |
| **实时值** | 摘要 + 变量表（最新/最小/最大/次数/实测频率）+ 迷你曲线（最近 120 点） |

- **命令表与脚本走同一套解析**：命令表先被 `tableToScript()` 转成脚本文本再交给 `dsl.js`，
  所以两处行为完全一致（也正因如此，「命令表 → 脚本」永远不漂）。
- 长读的 `as` 解码作用在拼起来的整块上；**实时值的"频率"按首末两次采样之间算**，
  不是"到现在为止"（后者跑停之后会一直往下掉，看着像采样变慢）。
- 「读分片助手」那张卡片**已经删掉**了 —— 分片现在是内部的（见 §4）。

### 6.1 「寄存器」面板（读一段 → 逐位改 → 写回）

调器件时 90% 的动作是"把某个寄存器的某一位打开/关掉，看看效果"。命令表能做，但每一步都要人肉把
`0x55` 拆成 8 个位、数第几位、再拼回十六进制 —— 这个 tab 把那套动作压成三步：**读取 → 点字节改位 → 只写改动**。

- **读**：`读取` 按「器件 / 起始 / 长度（默认 128 B = 16×8）/ 地址宽度（1 B / 2 B / 0 B 纯读）」走
  `session.readLong()` —— 超过 54 B 自动分片（128 B = 54+54+20 三笔），日志只出一行。
  「读法」给 `每片重发地址`（默认，最稳）与 `地址指针自增`（FIFO 型器件必须用）。
- **改**：点任意字节弹 `.bitpop`（与 `#panel` 页**共用同一套 CSS**，DOM 各一份）：8 个 47px 方块 +
  与原件不同的位套黄框 + `00/FF/取反/恢复原值` 快捷键；面板里也能直接敲十六进制。
  **改的只是内存里这份缓冲**（`cur`），`base` 是"读回来的器件现值" —— 黄框 = 与器件现状的差异。
- **写**：`只写改动` 用 `protocol.planWrite` 把"改过的下标"合并成片（相邻的合成一片、中间断开就分开写，
  每片自带 bump 过的子地址），`整块写回` 则整段下发。写分片上限可选 **51（协议上限）/32/16/8** ——
  **EEPROM 页写会回卷**（AT24C02 页 8 B、AT24C32 页 32 B），按页给才不写花；
  片间等待填 6 ms 左右给 EEPROM 的 **tWR**（写完一页期间器件不 ACK 下一笔）。
- 写回成功后 `base ← cur`（黄框清掉，"器件现值"跟着更新）。
- 🚨 **读完之后改过「器件 / 起始 / 地址宽度」就拒绝写回**：手里这份数据是从旧地址读回来的，
  照着新地址写下去等于把一段数据糊到别的器件/别的寄存器区上（对 EEPROM 尤其致命）。
  提示语要求先重新「读取」—— 这也是"黄框 = 与器件现状的差异"这条语义成立的唯一用法。
- 长写的地层是 `session.writeLong()`（与 `readLong` 对称）；分片计划在 `protocol.planWrite()`
  （纯函数，Node 自测直接打），面板**不自己切片**。

## 7. 内置示例（脚本区）

| 示例 | 内容 | 备注 |
| --- | --- | --- |
| 快速上手 | `scan` + `ping` 常见地址 + 试读 | 默认载入 |
| AT24C02 · 读 | 探测 / 读 16 B / **`rd 0x50 0x00 256` 一条读全片**（自动分片）/ 每 500 ms 定时读 | **只读，不动片子** |
| AT24C02 · 页写 | 页写 8 B + 等 tWR + 回读对账 + 每 500 ms 写读（20 轮自停） | ⚠️ **会改动内容**，标题里写明了 |
| MPU6050 | WHO_AM_I → 唤醒 → 采样率/量程 → **每 50 ms 一次读 14 B**，解出 ax/ay/az/tC/gx/gy/gz | 寄存器地址与换算逐条核过手册 |
| ADS1115 | 配置字逐位讲清 → 单次转换 → **每 200 ms 四通道轮流读**，解出 AIN0..3 电压 | 含 `0xC383`（单端 ±4.096V）/ `0xC583`（单端 ±2.048V）/ `0x8383`（**差分**）等常用配置字；并写明 **±4.096V 档受 VDD 限制**（3.3V 供电实际只能测到 3.3V） |
| Si5351 | 状态 / 输出使能(0x03) / **OEB 掩码(0x09)** / 三路控制字 / PLLA 与 MS0..MS2 参数块 + **每 500 ms 盯失锁**（20 轮自停） | **会写器件**：配成 CLK0=50 / CLK1=12.5 / CLK2=1 MHz（25 MHz 晶振；字节已**真机验证**）。写明空白件上电没频率、配置在 RAM 掉电即失；寄存器地图对着数据手册 + AN619 核过；PLL 软复位用 **0xA0**（流程图的 0xAC 会留下 Reserved 位） |

**收录原则**（写给以后维护的人）：
1. 寄存器地址与公式要**经得起对**（对着手册逐条核）；改之前先核。
2. **不确定的就不写进去** —— 这条不是"永远不写"，而是"**没验过就不写**"。Si5351 的频率合成参数
   一开始因为手上没硬件，只给公式 + 注释掉的两行；2026-10 用真机（探针 I2C 桥 + Si5351A@0x60 +
   25 MHz 晶振）把三路输出的每一字节验过之后，就改成**可直接跑的配置**，并注明"已真机验证"、
   标题打 ⚠（会写器件）。**验过之后就该把"不敢写"的注释拿掉**，别让它一直挂着。
3. **会改动器件内容的示例单独一份、标题里写明**（EEPROM 有写寿命）。
4. **注释里的十六进制也当代码看**：2026-10 这轮对账抓出两处"只是注释"的错 ——
   ADS1115 的 `0x8383` 被写成"同上但 PGA=010(±2.048V)"（真身是 **MUX=000 差分 AIN0-AIN1 · ±4.096V**，
   要单端 ±2.048V 是 `0xC583`）；Si5351 的 CLK0 控制被写成 `0x03`（那是**输出使能**且低有效，
   照抄 `wr 0x60 0x03 0F` 会把 CLK0..CLK3 关掉；CLK0 控制在 `0x10`），参数块 8 B 还少了
   `P1[17:16]` 那一位、也漏了必须的 PLL 软复位（`0xB1=0xAC`）。**示例文本是给人抄的，抄错就是错。**

## 8. 排障

| 现象 | 先看什么 |
| --- | --- |
| 一个器件都不应答 | 跑 **PINTEST**：`bit16=1 且问题位图=0` ⇒ 桥侧没问题，去查器件侧（接线/供电/地址/上拉）。`bit0..3` 用来看上拉有没有 |
| 读到全 `00` / `FF` | 器件在但寄存器不对：核对子地址与量程；全 `FF` 常常是没供电 |
| `E_NO_ADDR (3)` | 地址相位没 ACK：器件不在 / 地址写错（A0-A2 跳线）/ 没接 / 没供电 |
| `E_NO_ACK (4)` | 数据相位被 NACK：写保护、写周期没结束（EEPROM 的 tWR）、寄存器只读 |
| 偶发 `E_BUSY (2)` | 上一条还没做完。主机侧**已经自动重发**（最多 20 次），日志里不会出现 |
| 总线被拉死 | 点「总线恢复」（9 个 SCL 脉冲 + STOP + 控制器复位），然后重试 |
| 页面突然一个命令都不回、COM 口也打不开 | 已知现象（web-handoff §10）：**拔插一次 USB**。页面连续 3 次超时会提示并停掉自动轮询 |

### 真机上量到的两条事实（2026-10-02，本机 AT24C02 模块）

1. **写完之后"立刻读"并不一定 NACK**：本机这块模块在写完的同一毫秒里读回就是新数据
   （不是每块 EEPROM 都这样，数据手册说 tWR 期间不 ACK）。所以：
   **代码里不要依赖"必须 NACK"**，`delay 10ms` 是"给够时间"而不是"必须等出错"。
   假件（`app/i2c/mock.js`）按数据手册**严格 NACK**，比真机更严 —— 按它写出来的代码在真机上只会更稳。
2. 100 kHz 下读 8 B 约 **7.9 ms**（含 HID 往返），单笔事务耗时能从 STATUS 的 `last_ticks` 看到。

## 10. 踩过的坑（别改回去）

1. **`<input>`/`<select>` 必须包在 `<td>` 里**。直接往 `<tr>` 上 append，浏览器会把它们当"匿名单元格"，
   整行**竖着堆起来**（第一版就这么翻的车，`i2c-page.test.mjs` 第 2 节专门盯这条）。
2. **PINTEST 的问题位图在 bit8..15**，不是 bit0..2。写成 `v & 0x01` 会把"空闲 SDA/SCL=1"
   这两个正常信号当成故障 —— 桥一切正常却报"SCL 在事务里从未被拉低"。
3. **所有 HID 命令必须走同一条串行链**：`AkaLinkHid.xfer()` 同一时刻只允许一条在飞，
   而事务内部要连发 XFER + 多条 RESULT，中间还夹着 1.5 s 一次的 STATUS 轮询。
4. **浏览器同 URL 导航不会重载**（当成同文档跳转）—— CDP 脚本里必须显式 `Page.reload({ignoreCache:true})`，
   否则量到的是上一版代码（排查排版时被骗过一次）。
5. **计数器是探针侧累计的**（只有 RESET 清零）：真机脚本要按"本次新增"判，不能看绝对值
   （上一轮跑过的错误会留下来）。
6. **未使能时 `GET_CFG` 回 `actual_scl_hz = 0`** —— 页面显示"桥还没使能"，不要显示成 "0 kHz"。
7. **DOM 只写在冷路径上**：表格结果列与实时值面板都用 `requestAnimationFrame` 合并（一帧最多刷一次），
   日志用 `appendLogLine`。理由见 2026-10-01 的性能定标（同步写可见元素一次 ~5 ms、读 `scrollHeight` 一次 ~17 ms）。
8. **短等待用对原语**（`app/core/pace.js`）：RESULT 轮询间隔用 `waitMs`（不受后台限速影响）；
   配套 BPT1 固件上循环周期与 `delay` 由 probe 定时器执行，网页只取结果；假探针保留浏览器模拟。
   限制与超期/满队列行为见 [probe 周期任务](probe-periodic-bus.md)。
9. **轮询 RESULT 的跳出条件只能是 `PENDING` 清零**，别拿"完成计数（`DONE_CNT`）变了"当条件：
   `DONE_CNT` 数的是**成功**事务，失败那一笔它不动 —— 于是**每一笔失败都要白等满 `resultTimeout`（默认 2 s）**。
   实测被咬过：向不存在的地址发一笔要 2 s 才回来，扫描里几十个空地址就是好几分钟。
   协议文档说"想更严谨就比对 `DONE_CNT`"，那是在 `PENDING` 之外**额外**记一笔账，不是拿它当唯一判据。
   （回归：`i2c-proto.test.mjs` 第 9 节量"每笔失败事务的耗时"，不许接近 2 s。）
10. **稳态不要刷日志**：一轮 50 ms × 几行的循环 = 每秒几十行，日志环（600 条）十几秒就被冲干净，
    真正有用的历史反而没了。执行器只在前 2 拍写完整日志，之后转静默（结果列与实时值面板继续更新），
    错误仍报但每个任务限量 5 条。**长读的分片也走这条**：内部那 5 笔记 quiet，只出一行汇总。
11. **`table-layout:fixed` + 显式列宽**：命令表结果列里那段长十六进制会把 auto 布局的列宽整个撑开、
    把表格顶出横向滚动条（`td{max-width}` 在 auto 布局下**不生效**）。改成 fixed 之后，
    **没写宽度的列会平分剩余空间** —— 序号列因此曾经拿到 233px（六分之一屏），所以序号必须显式给死；
    「数据」与「解码 as」故意留 auto 吃掉余量。
12. **结果列里解码值排在前面**：列宽有限、省略号会吃掉尾巴；`ax=… az=…` 才是传感器读数的重点，
    原始十六进制日志里有全文、hover 也有 title。
13. **CDP 截图可能拿到上一帧**：页面在后台时渲染被降频，切完 tab 立刻 `Page.captureScreenshot`
    会拍出**上一个 tab** 的画面（实测被骗过一次）。截图前先 `Page.bringToFront` 并留一拍，
    顺便把 `dockTab` 打出来核对。
14. **实测频率要按"首末采样之间"算**，不能按"到现在为止"：后者在跑停之后会一直往下掉
    （实测跑完 5 秒还显示 15.5 Hz，而那一段本来是 20 Hz）—— 那是渲染时刻在变，不是采样变慢了。
15. **tab 内容块用 `display:flex` 而不是 block**：`.dockpage{display:none}` / `.dockpage.on{display:flex;
    flex-direction:column}` 是 `#dbg` 那套的原样 —— 里面靠 `flex:1 1 auto` 吃满高度的滚动区
    （命令表、实时值表、脚本文本框）只有在 flex 容器里才生效。改成 block 的话它们会按内容高度塌掉，
    tab 化就白做了。
16. **刷新要补在"刚显示出来"那一刻**：`display:none` 本身不影响 rAF，但**整个页面**被切走时
    浏览器会把 rAF 挂起 → 结果列的脏标记可能一直挂着。所以 `_dockSelect()` 里对 live/cmd
    各补一次重画/flush，"切页签回来"的 `onShow()` 也补一次。
17. **十六进制格式化别叠加前缀**（2026-10-03 做寄存器面板时踩的）：`protocol.hex2()` 自带 `0x`，
    再拼一个就得到 `0x0x2A`；而多字节地址 `join(hex2)` 会得到 `0x010x3C` ——
    地址文本一律用 `registers.addrLabel()`（自己按字节补零，只在最前面加一个 `0x`）。
18. **面板里的"写回"必须先和"读到的东西"对账**：读完之后用户改了器件地址/起始地址就写回，
    等于把**旧地址读回来的数据**写到新地址上（EEPROM 上就是覆盖别处）。`RegView.write()` 因此拿
    "读取时的指纹"（器件 + 起始 + 地址宽度）比一次，不一致就拒绝并提示重新读取。
19. **写长块必须显式给分片**（`planWrite` 的 `chunkMax`）+ EEPROM 还要给 `gapMs`：器件页写会回卷
    （AT24C02 页 8 B），而 tWR 期间不 ACK 下一笔 —— 这两条在 `i2c-registers.test.mjs` §D 里
    用假 EEPROM 钉死了（不按页写 → 回读与写入不一致；不等 tWR → 第 2 片失败）。
