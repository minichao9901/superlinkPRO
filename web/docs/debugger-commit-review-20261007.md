## 修正边界

- XIP 字节是 ELF 镜像，不是实时目标内存，也不是未经校验的“权威值”。
  相邻只读、已分配 PROGBITS 段可拼接；无 ELF、空洞、可写段、非分配段、
  文件截断、地址溢出均不可用。绝不补零或退回危险 SBA。
- 普通 SBA 读取失败最多清 sticky 错误，不调用 dm.init/ndmreset，不自动重读
  同一坏范围。目标现场不因刷新变量/内存被隐式重启。
- 暂停失败不会自动升级为系统复位；显式复位按钮仍可复位目标。
  停机后重新确认真实状态；状态未知不发抽象命令。GPR/CSR/PC 都适用。
- 寄存器刷新失败保留旧快照并报错，不合成零。
- 源码索引、目录遍历、缓存和 UI 绘制均拒绝旧异步任务覆盖新会话。
  无源码路径的 ELF 不触发整目录扫描。
- RISC-V XIP 代码校验不能比较 ELF 与自身；压力测试要求独立 GDB 校验记录，
  并明确不声称 Web 独立验证当前板上 Flash。实板须使用本轮重新生成的 oracle。
- M7 竞态例外由两套测试共用一个判据：CPU、DFSR、DWT、FPB、当前异常号、
  异常栈 PC/xPSR 都要符合；证据缺失保持失败。

## 为什么原来漏掉

原测试集中在单个段和有效映射，缺少无 ELF、跨段、空洞、跨禁读边界与溢出。
恢复成功被当成唯一目标，没有把“普通读取不能改变目标运行现场”写为不变量。
状态桩允许未知状态按缓存继续；源码测试没有交错完成的打开/遍历/读取请求。
GDB 和竞态例外需要审查例外本身，不能只看测试绿色。

## 验证与实板验收

离线回归覆盖完整 Web 测试、全模块语法检查，以及新内存/状态/源码竞态测试。
GDB 契约测试的 `--native` 运行公共压力靶源码的 Og/Os 两种本机编译；它不等于
ARM/RISC-V 实板 GDB 对照。本轮没有连接 6800EVK，也没有重新进行硬件压测。

实板须复跑：tcpecho 原复现流程；无 ELF/跨段常量读取；坏地址后目标不被自动
复位；复位后断点重装、继续/单步/局部变量/回溯；源码目录/ELF 连续切换；
RTT 同屏和原 6800EVK 不变量压测。若 SBA 真正卡死，显式复位/重连仍是恢复入口。
