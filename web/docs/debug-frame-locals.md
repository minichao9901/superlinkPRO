# 调试器栈帧、局部变量与参数

本次仅增加 Web 调试器功能，不修改探针协议、固件、ADC/DAC、SPI/I2C、RTT 或 JScope。
共享的 `app/elf/` 解析器保持不变。新模块 `app/dbg/cfi.js`、`app/dbg/locals.js`
分别负责栈展开和局部变量位置求值，通过调试器会话既有独占队列读取目标。
两者按需加载，无后台采样任务；未使用调试器时不产生额外目标访问。

## 使用

载入与板上固件一致、未裁剪调试信息的最终 ELF，暂停目标后点击「栈回溯」。
调用栈的按钮选择栈帧，源码和「局部变量 / 参数」面板随之切换。
结构体、数组可以展开，值读取失败时显示原因。寄存器面板仍表示真实当前内核，
切换调用者帧不会写寄存器、修改内存或恢复运行。

```text
bt 16
frame 1
info locals
info args
frame 0
```

`frame` 无参数显示并刷新当前选择；序号从0开始。
`locals` / `args` 是两个 `info` 子命令的简写。
`bt scan` 仍仅显示候选地址，不能用作局部变量的帧上下文。
运行、单步、复位、写寄存器、写内存、断开或更换 ELF 后必须重新回溯。
选择帧前还会检查暂停状态、PC、SP 和 ELF 身份。

## 编译与支持范围

首版面向 Cortex-M、32位小端 ELF 和常见 GCC DWARF4/5 调试信息。
建议 `-g -Og`；不必因为调试功能关闭目标全部优化。
需要 `.debug_frame` 或 ARM EHABI 段；最终 ELF 必须保留 `.debug_info` 等调试段。
CFA 和 frame_base 是不同概念，局部变量按函数 `DW_AT_frame_base` 求值，
不把 SP 或帧指针直接当作统一基址。

- 优先使用 DWARF32 `.debug_frame` CIE v1/v3/v4，支持位置推进、CFA、
  寄存器保存/恢复、状态栈、offset/value/register/same/undefined 等常见核心规则。
  匹配的 CFI 可描述函数序言/尾声；无匹配表项时回退已有 EHABI。
- 变量支持函数和活动词法块/内联块、抽象来源/声明关联、常量、寄存器、
  breg/fbreg/CFA、常见整数位置运算与解引用、DWARF4 `.debug_loc/.debug_ranges`、
  DWARF5 `.debug_loclists/.debug_rnglists` 及索引表。
- 每帧保存寄存器和「可恢复寄存器集合」。调用者易失寄存器不会沿用被调用者的值；
  不可恢复、已优化掉、缺少位置或不支持表达式时明确显示原因。
- 目前不支持 RISC-V 自动展开、`.eh_frame`、CFI 表达式、浮点寄存器恢复、
  分片/多寄存器变量、entry_value/typed expressions、独立的内联虚拟栈帧。
  优化、尾调用及缺失展开信息可能使调用链不完整；不会把候选扫描冒充完整调用链。
- 默认回溯16帧，可选1..64帧，原栈读取窗口默认4096字节。
  局部变量最多128项，单变量最多512字节，总读取预算8192字节；表达式和列表均有边界。
  异常硬件帧恢复后保留已有跨栈停止策略。

规范依据：[DWARF 5](https://dwarfstd.org/doc/DWARF5.pdf) §2.5、§6.4、§7.7。

## 验证

`make test` 已包含新的 `dbg-frame-locals.test.mjs`。
使用仓库中已编译的 STM32F103 GCC ELF，独立对照 readelf 展开/位置表，验证
序言/尾声的 CFA、寄存器恢复、参数从寄存器迁移到栈、PC 对应的位置与帧切换。
另有 DWARF5 索引位置/范围、作用域、结构体/数组、异常读取、取消、旧缓存、
相同 PC 下的写操作失效和源码回绘测试。其他模块运行既有完整回归。
这些是离线测试，不代表本次代码已经过浏览器布局、连接板卡或吞吐实测。

板上验收：在 F103 的多层调用、递归和带局部数组的函数内分别暂停；逐帧与 GDB
对照函数、SP/CFA、参数和局部值；检查单步、继续后旧值清除。
再确认 RTT/JScope、SPI/I2C、ADC 页的既有连接/吞吐行为。
