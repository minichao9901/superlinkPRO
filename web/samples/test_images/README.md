# BMP 测试图样（samples/test_images）

给「SPI/QSPI 屏」页的**图片通路**做回归与肉眼验收用的一组 BMP（`app/spi/image.js` 的
`parseBMP()` 支持 16/24bpp，这组就是照着它的分支铺的）。

## 两组一一对应（同名同尺寸，**只有像素格式不同**）

| 目录 | 格式 | 说明 |
|---|---|---|
| `./`（顶层，37 张） | **36 张 24bpp BI_RGB** + `fmt_16bit.bmp`（16bpp BI_BITFIELDS） | 常规一套，另外塞了**一张** 16bpp 当对照 |
| `bpp16/`（37 张） | **36 张 16bpp BI_BITFIELDS（RGB565 掩码）** + `fmt_24bit.bmp`（24bpp） | 同一批图重编码成 16bpp，另外留了**一张** 24bpp 当对照 |

> 两组的文件名**完全一一对应**（各 37 个，名字相同）。所以"同一张图两种格式刷出来应当一样"
> 这件事可以直接用 `diff` 式对比：同一名字，一个在顶层、一个在 `bpp16/`。
> 16bpp 那批带 3 个 DWORD 掩码（`biCompression = 3`、数据偏移 66），不是"裸 RGB565"；
> 24bpp 那批是 `BI_RGB`、数据偏移 54。

## 尺寸分布（顶层）

| 尺寸 | 张数 | 用途 |
|---|---|---|
| **240×296** | 33 | AXS15352 那类小屏的整屏尺寸（也正好是屏页预览画布的固有比例） |
| 64×64 / 16×16 / 120×40 / 41×20 | 各 1 | 小图与**非 4 像素对齐**的边界（开窗对齐全按 4 像素对齐，靠它们验） |

## 每张图在看什么

| 名字 | 看什么 |
|---|---|
| `testcard` / `mixcard` | 综合图：色块 + 灰阶 + 细线，一眼看整体是否正常 |
| `bars_8` / `bars_gray16` | 8 级彩条 / 16 级灰阶 —— 看量化台阶与灰阶是否偏色 |
| `checker_1px` / `_8px` / `_16px` / `grid_4px` | 1/8/16 像素棋盘与 4 像素网格 —— 看缩放、像素对齐、有没有丢列 |
| `lines_1px_h` / `_1px_v` | 单像素横线/竖线 —— 看细线保真（缩放最容易吃掉它） |
| `gradient` | 连续渐变 —— 看色带（banding）与 dithering 行为 |
| `solid_r/g/b/white/black/gray` | 纯色 —— 看**红蓝交换**、对比度与色彩范围 |
| `half_r` `half_g` `half_b` | 半屏纯色（左半/右半）—— 同上，更容易看出串色 |
| `half_rb` `half_rg` `half_gb` | 两个半屏各一色 —— 快速判 R/B 或字节序翻错 |
| `mix_r` `mix_g` `mix_b` `mix_rb` `mix_rg` `mix_gb` | 双色混合图 —— 同上，逐通道排查 |
| `landscape_1..5` | 横竖/长宽比不同的几张 —— 验排版映射（`composeImage()` 的四种模式） |
| `small_*` | 小于一屏的图 —— 验摆放与 4 像素对齐开窗 |

## 怎么用

1. 网页「SPI/QSPI 屏」→「刷屏」→ 把 BMP **拖进去**（或点选）→ 预览 → 刷；
2. 想验"格式差异不影响结果"：同一个名字，先刷顶层的、再刷 `bpp16/` 里那张，两张应当一致；
3. 想验**色序开关**：刷 `solid_r.bmp`，不对时只翻「R/B 交换」或「字节序」**其中一个**（别同时翻）。

> 这批图是用户提供并入库的素材（2026-10），**没有配套生成脚本**；要加新样本直接放进来、
> 保持"顶层/bpp16 同名成对"的约定即可。
