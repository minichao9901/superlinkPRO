# STM32F103 · scope（HSS 采样）测试固件

给「J-Scope 波形页」（探针侧 HSS 采样）用的**靶子**：每个被采样的量都有**精确已知的数学波形**，
所以"采样率对不对、有没有混叠、丢了多少、有没有撕裂读"都能**客观判定**，不用靠肉眼看波形。

- 时基：HSI 8 MHz（不配 PLL）→ SysTick 每 800 周期 = **10 kHz**，ISR 里所有量一次更新完。
- 目标固件**不占任何外设**（只开时钟 + SysTick），与兄弟例程 `stm32f103_rtt_speed` 同一风格。
- **没有 D-cache**（F103 是 CM3）→ 这块板子量出来的问题一定是采样/协议本身，不会掺进 H7 那种
  "AHB-AP 读到 cache 旧值"的干扰（那条要在 H7 上单独验）。

## 1. 变量契约（`t` = g_tick，10 kHz 计数）

| 变量 | 地址¹ | 类型 | 应有值 |
|---|---|---|---|
| `g_pack.f_sin` | 0x20001014 | f32 | `SIN100[t%100]/1000` —— 100 Hz 正弦 ±1.0 |
| `g_pack.f_tri` | 0x20001018 | f32 | 100 Hz 三角，峰值在 `t%100==50`（与正弦差 90°） |
| `g_pack.i_tick` | 0x2000101c | i32 | `t` |
| `g_pack.u_ramp` | 0x20001020 | u16 | `t % 1000`（100 Hz 锯齿） |
| `g_pack.i_sq1k` | 0x20001022 | i16 | `(t%10<5) ? +1000 : -1000` —— **1 kHz 方波** |
| `g_pack.u_cnt` | 0x20001024 | u8 | `t & 0xFF`（约 39 Hz 回绕） |
| `g_pack.i_saw` | 0x20001025 | i8 | `(int8_t)(t*3)` —— 8 位锯齿，步进 3 |
| `g_pack.u_hi` | 0x20001028 | u32 | `0x10000000 \| (t & 0xFFFF)` —— **高位非零，验 u32 精度** |
| `g_lfsr` | 0x20000000 | u32 | xorshift32（宽带伪随机） |
| `g_far_cnt` | 0x20000008 | u32 | `t` |
| `g_far_sq100` | 0x2000000c | i16 | 100 Hz 方波 ±1000 |
| `g_isr_count` | 0x20001010 | u32 | `t`（与 `g_tick` 同值 → 验两个地址都对） |
| `g_pair_a` / `g_pair_b` | 0x2000102c / 0x2000102e | u16 | `t` / `~t` —— **撕裂自检**：`a^b != 0xFFFF` 即"读到两次 store 之间" |
| `g_pulse` | 0x20001030 | u8 | `(t%2000 < 100) ? 1 : 0` —— 5 Hz 脉冲、5% 占空比（**触发测试**用） |
| `g_ramp64` | 0x20001038 | f64 | `1.0 + t*1e-6`（主循环更新，验 8 字节载荷/浮点精度） |
| `g_sq5k` | 0x20001040 | i16 | `(t&1) ? +1000 : -1000` —— **5 kHz 方波：采样率 < 10 kHz 必然混叠** |
| `g_tick` | 0x20001044 | u32 | `t`（**主对齐量**） |
| `g_hole[4096]` | 0x2000000e | u8[] | 占位（不采），作用只是把地址拉开 4 KB |

¹ 本机构建实测（`build.ps1` 每次会打印一遍；换编译器/改代码后地址会变，**以 nm 为准**）。

**更新顺序 = 契约的一部分**（主机据此放宽断言）：先 `g_tick`，再 `g_pack` 各字段（逐个 store，
**不是原子快照**），最后散落量。所以任何读到的值都可能落在"上一 tick"⇒ 断言要允许 ±1 tick。

## 2. 地址分两块 → 正好对比"读计划"的两条路径

```
span A  0x20000000 .. 0x2000000e   14 B   （g_lfsr / g_far_cnt / g_far_sq100）
        ── 4 KB 空洞（g_hole 占位）──
span B  0x20001010 .. 0x20001048   56 B   （其余全部）
```

按 `docs/scope-page.md` §6.1 的时钟模型（45 MHz：每字节 ≈0.284 µs，每块固定开销 ≈5.6 µs）：

| 采样方案 | 每样本 | 上限（模型估算） |
|---|---|---|
| 8 个字段全取 `g_pack`（**一个 span，24 B**） | ≈12.4 µs | **≈81 kHz** |
| 跨 span 取 8 个（A 14 B + B 56 B） | ≈31 µs | **≈32 kHz** |
| 朴素：8 次 `swd_read_memory()` | ≈54 µs | ≈18 kHz |

**这些是模型估算，不是实测** —— 页面里会显示它自己的估算，真值要等探针固件的标定（M0）。

## 3. 编译 / 烧录 / 验收

```powershell
pwsh -File build.ps1          # 编译（arm-none-eabi-gcc 10.3，-g3 -gdwarf-4）
pwsh -File build.ps1 -Clean
pwsh -File flash.ps1          # OpenOCD + CMSIS-DAP 烧录（自动找 0.12+ 的 openocd）
pwsh -File flash.ps1 -Erase   # 先整片擦除

python check.py               # ★ 客观验收：halt → dump RAM → 按契约逐项核对 + 复测 10 kHz 时基
python check.py --hold        # 跑完保持 halt（排障）
```

`check.py` 会做两件事：
1. halt 住目标、dump 0x20000000 起 8 KB，**逐个变量核对契约**（浮点容差 2e-6，整型精确比对；
   每个量允许 `t` 或 `t-1`，被 halt 打断的 `g_pair_a/b` 会报"撕裂"而不是判失败）；
2. 让目标跑 3 s 再 halt 一次，用 `Δtick` 反测时基（偏差 >3% 才判失败）。

> `check.py` 用的是 pyelftools 读符号表取地址 —— 所以**改了变量名/结构体布局要同步改它**。

## 4. 怎么用它验证 scope 页面

1. 页面里载入 `build/fw.elf`，勾选 8 个变量（建议先勾 `g_pack` 那一组：一个 span 的快路径）；
2. 采样率定成 **10 kHz 以上**（高于 5 kHz 那个方波的两倍才能看清它；定到 30 kHz 才不混叠）；
3. 对账办法（都可以自动化）：
   - **速率**：`g_tick` 的斜率必须 ≈ 采样率（同一采样率下连续两点差 1，除非丢样本）；
   - **丢样本**：`g_tick` 出现跳变 > 1 ⇒ 中间丢了样本，跳变量应等于页面的 `dropped` 计数；
   - **波形**：按 `g_tick` 反算其余通道应有值，逐点比对（`check.py` 里那张表就是参照）；
   - **撕裂**：`g_pair_a ^ g_pair_b != 0xFFFF` 的样本占比 —— 采样率越高、这个比例越高，
     这就是"8 个变量不是一个原子快照"的**量化证据**；
   - **混叠**：把采样率降到 6 kHz 看 `g_sq5k`（5 kHz 方波）变成什么低频假波。
4. 采集完导出的 CSV，可以直接和 `check.py` 的契约表对拍。

## 5. 坑（本固件已踩/已处理）

1. **`g_hole` 会被 gc 掉**：`-fdata-sections` + `--gc-sections` 下，没有任何引用的 4096 B 数组
   连同"地址空洞"一起消失（实测：bss 只涨 8 字节，两个 `g_far_*` 又贴回来了）。
   现在 `main()` 里有一句 `g_hole[0] = 0;` 保命，注释里写了原因 —— 别删。
2. **必须 `-gdwarf-4`**：本机 GCC 10.3 默认就是 4，但 GCC 11+ 会默认切到 DWARF 5；
   scope 页面第一版的解析器只吃 DWARF 4，所以这里显式写死，免得工具链一升级就解析不出来。
3. **软浮点**：CM3 没有 FPU，`(float)×0.001f` 是 `__aeabi_i2f`+`__aeabi_fmul`（约 100 周期）。
   两个这样的运算放在 10 kHz ISR（800 周期预算）里占约 25%，可接受；**别再加**。
   `g_ramp64` 的 double 运算故意放在 ISR 外的主循环里。
4. **烧录用的 OpenOCD 必须 0.12+ 且显式 `cmsis-dap backend usb_bulk`**（CMSIS-DAP v2 是 bulk 传输）。
   本机可用：`E:\Share\env-windows\xpack-openocd-0.12.0-6`。
   `flash.ps1` 会自动找（ESP-IDF 已卸载，所以不能只认它那条路径）。
5. 烧了本固件之后，之前那个 RTT 洪水固件就没了 —— 要回去就再烧
   `..\stm32f103_rtt_speed`（那份 `flash.ps1` 的 openocd 查找路径已失效，把 `-OpenOcd/-Scripts`
   指到 xPack 那份即可）。
